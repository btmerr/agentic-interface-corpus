# Agentic & AI interface brief — 2026-10-12

**Theme:** An approve button is not a security boundary. Binding the decision to the exact action that executes — digest at use time, fail closed on mismatch, and keep permission prompt text out of the tool-call display state — is the load-bearing design. Two papers measure where that binding breaks; a Microsoft ADR and Cloudflare's Codemode spell out the repair; Cursor and Claude Code are shipping the smaller craft that makes the binding inspectable.

1. **[Approval Laundering: Systematizing Approval–Execution Binding Failures in AI Coding-Agent Harnesses (arXiv 2609.38983)](https://arxiv.org/abs/2609.38983)**: the approve click can authorize a different action
   A Fudan working draft instruments Claude Code's PreToolUse hook and names six laundering classes — Scope, Argument, Temporal, Tool, Delegation, and Semantic — where the harness dispatches something other than what the human approved under an explicit stated policy. Measured Bound-Gap Rates on Claude Code reach 1.00 for Scope and Temporal, 0.95 for Delegation, and 0.45 for Argument (N≈19–20 per class). Their Approval Token (HMAC over principal, agent, session, tool, arguments, scope, expiry) eliminates Delegation and a seeded Temporal case, but by design cannot catch Scope or Argument effect divergences that leave every recorded field unchanged (hooks, PATH shadows). That negative result is the design lesson: field-only credentials at the tool-call boundary are not enough when the blast radius lives one process below. Credibility: medium-high. Controlled repeated-measures on one harness, honest about synthetic Temporal seeding and single-harness scope; still a working draft, not peer-reviewed. Weight: high.

2. **[Loopjacking: Hijacking Human-in-the-Loop Approval (arXiv 2609.21081)](https://arxiv.org/abs/2609.21081)**: representation mismatch vs post-approval substitution
   Independent work on the same A-approved-then-B-executes failure, aimed at orchestration products rather than coding CLIs. Representation-based Loopjacking (OpenClaw shell wrapper showed incomplete argv; fixed in 2026.2.24) and post-approval state substitution (Agno AgentOS and a conditional LangGraph Agent Server composition) are the two variants. OpenAI Agents SDK's ordinary per-call serialization is the negative control that rejects mutated B. The portable repair is complete canonical rendering plus exact use-time comparison, or denying unauthorized pending-state mutation. Complements Approval Laundering: same invariant, different product surface. Credibility: medium-high. Purposive product set with exact versions and controls, not a prevalence study; single-author with an evidence archive. Weight: high.

3. **[ADR 0030: Action-Bound, Fail-Closed Approval Protocol (Microsoft Agent Governance Toolkit)](https://microsoft.github.io/agent-governance-toolkit/adr/0030-action-bound-approval-protocol/)**: the protocol form of the same invariant
   `require_approval` is a suspended decision, not allow and not deny. The runtime binds a SHA-256 digest of the exact executable request (agent, subject, tool, schema version, resource, parameters), persists a durable approval request with expiry, chains authenticated human entries, and revalidates digest + policy version + chain version immediately before execution — fail closed on timeout, restart, or mismatch. LLM output may advise a human; it cannot mint a terminal allow. This is the checklist to steal for a harness approval ledger: digest, consume once, never trust a body-supplied approver string. Credibility: high. It's a primary Microsoft governance ADR with explicit acceptance tests; implementation maturity outside the ADR is unclear. Weight: high.

4. **[Cloudflare Agents Codemode: approvals via abort-and-replay](https://github.com/cloudflare/agents/blob/HEAD/docs/codemode/approvals.md)**: treat the approval queue as racy
   Tools mark `requiresApproval: true`; the run aborts, logs pending actions, and continues only by replaying the durable tool-call log after `approve(executionId)`. `approve()` is a safe no-op if the run is no longer paused — another tab, operator, or concurrent turn may have already resolved it — so UIs must refresh the queue rather than assume the click still owns the run. Contrasts Gatekeeper's simulate-ahead pending state with simpler, fully durable abort-and-replay. For a multi-agent approval surface, race-safe resolve is as important as the approve affordance itself. Credibility: high. Primary product docs from Cloudflare's agents SDK. Weight: medium-high.

5. **[Cursor 3.1: tiled Agents Window, plan tabs as documents, diff→file](https://cursor.com/changelog/3-1)**: parallel supervision gets panes, not just tabs
   Split the Agents Window into persistent tiled panes, drag agents into tiles, and keep the layout across sessions. Plan tabs gain file-like behaviors (dirty tracking, reload on change, save/copy/export markdown). Diff-to-file jumps to the exact line with full editor power. Complements last week's ParallelPilot finding that awareness needs a cheap path to evidence: the tile and the plan-as-document are that path in a commercial Agents Window. Credibility: high. Primary vendor changelog; incremental craft, not a measured study. Weight: medium.

6. **[Claude Code: approval integrity fixes in the permission path](https://code.claude.com/docs/en/changelog)**: plugins and auto mode cannot skip the human dialog
   Recent changelog fixes close three binding holes: a plugin `tool.check` allow can no longer run a tool that needs a question or plan approval without showing its dialog; plan mode is restored on `--resume` / `/resume`; and cloud approval prompts no longer offer a no-op "Always allow" for connector tools an organization set to require approval. Also: plan mode still routes file edits and shell writes through `canUseTool` even under dangerous skip flags. Small, but they treat the approval dialog as a privilege that hooks cannot launder away — the product-side half of this week's theme. Credibility: high. Primary changelog; behavior-only, no rates. Weight: medium.

**Takeaway for a non-chat+diff harness:** Model the approval as a durable, action-bound credential (digest over the exact tool+args+scope+agent+session), revalidate at dispatch, and fail closed on mismatch or timeout. Expect Scope/Argument-class failures below the tool-call boundary — hooks, PATH, child processes — so pair field binding with effect sensors. Keep permission prompt copy off the tool-call display state (ACP v2's subject split is the right shape). Build the approval queue for concurrent operators: every resolve is idempotent and refreshable. Give parallel agents panes and make every plan a first-class, exportable document one click from the diff.
