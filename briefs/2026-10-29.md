# Agentic & AI interface brief — 2026-10-29

**Theme: Every output should say what it covers and what it skipped.** Today's papers keep finding the same gap: an agent's "PASS", a reviewer's "looks valid", a tool's partial page and a model-agnostic harness claim all sound complete while covering only part of the job. The useful designs make the gap explicit. They route each action by what it could break and whether it can be undone, return results with "here's what's left", and keep claims apart from checks. GitHub's Universe launches push the same surfaces to goal-level projects and team-owned automations, which raises the bar for showing who did what.

1. **[CASEL: Consequence-Aware Selective Execution for Reliable Long-Horizon Tool-Using Agents](https://arxiv.org/abs/2610.36570)** (arXiv 2610.36570), plus [Small agents should know what their tools do](https://arxiv.org/abs/2610.35981) (2610.35981), route each action by its blast radius, not by the model's confidence
   CASEL picks, for every proposed tool call, one of six modes: run it, verify first, sandbox, ask a clarifying question, ask for approval, or abstain. It decides by combining failure probability with consequence, reversibility, ambiguity and how fresh the evidence is. In a 20-seed simulation with 120,000 actions per seed, it cut harmful trajectories from 14.75% (an uncertainty-ranked gate) to 7.02%. A plain "probability times consequence" gate got similar harm but sent 45% more actions to a human, and dropping reversibility pushed harm back to 15.53%. The companion EffectWorld paper makes every tool declare its effect, whether it's idempotent, and what it reads and writes, which lets a replay check decide whether a trace was effect-safe without a judge model. For your harness: give each tool an effect declaration, and show the routing decision on each action card ("ran directly: read-only", "held for approval: irreversible write"). Approval should be the scarce channel for irreversible actions, not the default for anything uncertain. Credibility: medium. CASEL is simulation-only and the authors say outright that intervention effectiveness is assumed; EffectWorld is a two-author benchmark with strong small-model gains. Weight: medium-high.

2. **[PROBE: Frontier Coding Agents Find Different Bugs Than Maintainers Fix](https://arxiv.org/abs/2610.35987)** (arXiv 2610.35987), plus [PASS Is a Claim, Not an Observation](https://arxiv.org/abs/2610.35950) (2610.35950), "valid" isn't the same as "what mattered"
   PROBE uses all 2,457 bugs maintainers fixed over 18 months in 20 repositories as a reference. Frontier agents asked to find bugs reach under 21% recall and under 9% precision against it, and stronger models raise recall (8% to 17%) without raising precision. Yet LLM and human evaluators judged 85% of findings valid, and the kinds of bugs agents find look alike across agents and differ from what maintainers fix. The smaller PASS paper re-checked 10 self-declared fixes from a live multi-agent system: among claims with enough detail to check, half had no fix at the claimed call site. For your harness: a findings list should show coverage against something real (past fixes, owned areas, test failures), not just a count of plausible issues, and a "fixed" badge should only light up when a separate check found the change where the agent said it was. Credibility: high for PROBE (Martin Vechev's group at ETH, large real reference set); low for PASS (10 claims from one system), useful as an illustration only. Weight: medium-high.

3. **[Stratum: Repository Memory for Coding Agents Beyond the Context Window](https://arxiv.org/abs/2610.36153)** (arXiv 2610.36153), every tool response says what it returned, what's left, and what it cost
   Stratum is a tiered memory that lives with the repository and is served through "page-safe" tools: each response states what it returned, what remains, and the cost. Across 752 real bug-fix commits the median fix touched two files, and those plus their imports were under 10% of the repo, so the bottleneck is choosing what to load, not window size. A fresh agent that inherited an earlier session's notes (written by a different model) found the root-cause file in 21 of 24 trials versus 6 of 24 for retrieval alone, at 4.5x lower median token cost. For your harness: make "returned N of M, here's the rest" the standard shape for every tool result, which directly fixes yesterday's silent JSON truncation (2610.36114), and show inherited session notes as a visible, editable object at session start. Credibility: medium. A design sketch with a small eight-bug experiment, but the statistics are clean. Weight: medium-high.

4. **[kw-bench: Breaking Frontier Harnesses on Real-World Tasks](https://arxiv.org/abs/2610.36405)** (arXiv 2610.36405), below the frontier, the harness decides how far a model gets
   The task is a five-year VAT reconstruction from raw extracts across three generations of SAP, graded deterministically to the cent. On the same mid-tier model (DeepSeek v4.1 Flash, two hours), OpenCode scored 0.542 and micro-cc 0.528, while Claude Code and Codex each scored 0.00 away from their home models. The author says what beat them was failing to keep many weak signals alive across a long session. On Claude Opus 5.5, micro-cc and Claude Code both nearly solved it in 22–25 minutes. For your harness: if you plan to be model-agnostic, test on weaker models, and give long investigations a visible "open leads" board so weak signals aren't lost when context turns over. Credibility: low-medium. Single author, one task family, and the four-harness comparison looks like one run each; treat it as a sharp anecdote, not a ranking. Weight: medium.

5. **[GitHub Universe: Copilot app projects and computer use](https://github.blog/changelog/2026-10-28-github-copilot-app-universe-releases)**, plus [shared Copilot Automations](https://github.blog/changelog/2026-10-28-build-shared-workflows-for-your-team-with-copilot-automations), [Agentic Workflows GA](https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available) and [Copilot Fusion](https://github.blog/changelog/2026-10-28-route-and-orchestrate-models-with-github-copilot-fusion), the unit of work moves from session to goal
   Shipped Oct 28:
   - **Projects (public preview):** you give Copilot a goal and context spanning repos, mocks, Slack threads and notes. It runs as many agents as needed in the background, checks in when it needs you, and brings back PRs for review. Computer use on macOS and Windows asks before controlling an app.
   - **Shared automations:** they belong to the repository, act as Copilot rather than as a person, bill the repo owner, and keep a change history of prompt, tools and triggers.
   - **Agentic Workflows GA:** Markdown compiles to Actions YAML, read-only by default, sandboxed behind a firewall, with "safe outputs" and a separate threat-detection job that scans proposed changes before they apply.
   - **Fusion GA:** routes each prompt as a single model, a cascade (a cheap draft escalated if a check fails) or a critique loop, and you can watch which path it chose.

   For your harness: this is the fleet-level surface to beat. Show the goal, the agents working on it and what's waiting on you as the primary view; give shared automations an owner, an acting identity and a diffable history; and show the routing path (cascade or critique) on the turn. Credibility: high for what shipped (primary changelogs); the productivity numbers are vendor and customer quotes, so discount them. Weight: medium-high.

6. **[ACP: spell out close's relationship to cancel (PR #2610)](https://github.com/agentclientprotocol/agent-client-protocol/pull/2610)**, plus [prompt response has no fixed order (#2607)](https://github.com/agentclientprotocol/agent-client-protocol/pull/2607), [replay covers retained history only (#2613)](https://github.com/agentclientprotocol/agent-client-protocol/pull/2613), and [the v2 session lifecycle (#2579), now merged](https://github.com/agentclientprotocol/agent-client-protocol/pull/2579)
   Merged this morning (about 6:55–7:40 AM PT), all v2:
   - **#2610:** closing answers pending permission requests as a cancel would, also stops background work (cancel doesn't), and now must cancel queued prompts. After the close response the agent sends nothing else for that session.
   - **#2607:** the prompt response has no fixed order relative to the user-message acknowledgment, the agent's output, or even the `idle` update. Clients must not infer ordering from it.
   - **#2613:** replay from the start covers only the history the agent kept, which may not be the whole conversation, and there's deliberately no completeness signal.
   - **#2579**, open in yesterday's brief, merged yesterday about 8:36 AM PT.

   For your harness: offer "stop" and "close" as different actions, because only close kills background work and queued prompts. Drive "done" from the idle state, never from the prompt response arriving. When you rebuild a timeline from replay, mark it "as retained by the agent" rather than implying it's the full transcript. Credibility: high (primary spec changes by the maintainer). Weight: medium.

**Takeaway for a non-chat+diff harness:** Route each action by what it touches and whether it can be undone, and show that routing on the card. Keep claims and checks visually separate, and measure findings against real coverage. Make "here's what's left" part of every tool result and every replayed timeline. Test on weak models too, because that's where the harness matters. Treat goal-level projects and team-owned automations as the new baseline for fleet views.
