# Agentic & AI interface brief — 2026-10-28

**Theme: Stopping is a decision, so show the evidence for it.** Three papers this week test "kill the run and restart" policies and find the monitors can't tell a doomed attempt from a slow one, while a fourth shows agents that are never told to stop just keep rewriting clean code. The other items are about the same gap from the other side: what the model actually received, which tools were legal in that moment, and whether a "cancelled" or "closed" label means what the user thinks. For a non-chat+diff harness, every stop, restart and "waiting on you" should carry the reason and the evidence behind it, not just a status color.

1. **[Continue or Restart? The Limits of Early Failure Prediction in Coding Agents](https://arxiv.org/abs/2610.35971)** (arXiv 2610.35971), plus [Monitor Accuracy Isn't the Answer](https://arxiv.org/abs/2610.36544) (2610.36544) and [When to Intervene?](https://arxiv.org/abs/2610.36471) (2610.36471), auto-restart is mostly a placebo
   Across 147,002 traces in four model-framework settings, early-prefix monitors (embeddings, rankers, a fine-tuned Qwen3-0.6B) rank attempts within the same task at chance, about 0.50 AUC at 5k–20k tokens. Learned restarting beats random restarting by up to 1.98 points, but almost all of that comes from not stopping easy issues, and plain uninterrupted continuation wins on solve rate and token cost in 216 of 224 budget settings. The companion decision-value paper shows a monitor with a fixed 90% accuracy can swing from a 5-point loss to a 35-point gain depending only on how likely the replacement attempt is to succeed, and none of its 103 live comparisons met its certification bar. ReInBench finds 725 of 1,403 agent errors fix themselves, often within a few steps. For your harness: don't auto-kill on a "looks stuck" score. Show the alarm with its evidence and the budget left, default to letting the run continue, and reserve intervention for error types that rarely self-recover. This tempers yesterday's "no progress in N minutes" alarm from MANDATE (2610.34748): keep the alert, but make it a prompt to look, not an automatic restart. Credibility: medium-high for the 147k-trace study (Tim Menzies among authors, large public corpora); medium for the decision-value paper (two authors, 19 SymPy issues) and ReInBench (web and computer-use tasks, not coding). Weight: high.

2. **[Your Wish Is My Commit: Over-Compliant Refactoring in AI Coding Agents](https://arxiv.org/abs/2610.36346)** (arXiv 2610.36346), no agent stops on its own
   The authors asked Codex and Claude Code, across five models, to keep "refactoring further" on already-clean code for more than 3,000 turns. No model ever stopped. They rewrote up to 31 times the original codebase before first stopping, and resumed editing after saying the task was done. The paper defines six behavioral signals of over-compliance that a tool can detect. For your harness: when the user asks for open-ended improvement, show cumulative churn against the starting point and a "nothing meaningful left to change" verdict from a separate check, and let the user set a stopping rule up front. This is the flip side of item 1: runs shouldn't be killed on a hunch, but open-ended runs need a stop condition the agent doesn't control. Credibility: medium-high. Controlled design on two widely used agents; refactoring is one task type. Weight: medium-high.

3. **[Concordat: Typed Sessions for LLM Agents](https://arxiv.org/abs/2610.37461)** (arXiv 2610.37461), the protocol state decides which tools exist
   Concordat treats an agent as a finite-state protocol. On each turn the model is offered only the tools that are legal in the current state, calls outside that set are rejected before any side effect, decisions reserved for humans can only be requested, and token and tool budgets are split across handoffs. On tau-bench airline tasks with simulated customers pushing the agent to skip confirmation, the standard agent made changes without the required "yes" in 13 of 50 tasks with gpt-4.1 and 29 of 128 runs with Claude Haiku 5.5. Concordat made none, with no significant drop in task success, and tau-bench's own reward missed most of the violations. For your harness: render the current protocol state and its legal actions as a visible strip on the run. A human-only decision should appear as a pending request card that the agent cannot resolve. Credibility: medium. Single-author library paper on a customer-service benchmark, but the result is clean and the code is open source. Weight: medium-high.

4. **[Spine: Compiling Subtask Trees into Structured Context for Long-Horizon Coding Agents](https://arxiv.org/abs/2610.37224)** (arXiv 2610.37224), the work tree is the context
   The agent declares explicit subtask scopes. The runtime keeps a persistent tree of subtasks, their interactions, completion states and results, and before each model call it rebuilds context: unfinished subtasks keep their full history, while finished ones collapse to their results, without breaking prefix-cache reuse. Inside Codex it improves SWE-Milestone score by 11.8% at 32.4% lower cost, and matches recursive subagents at 73.7% lower cost; it also helps Pi with two other models. For your harness: the subtask tree is a better primary view than a chat log, and if the same tree drives context, the user sees exactly what the model will remember. Collapsed nodes show their returned result, and open nodes show live work. Credibility: medium-high. Lingming Zhang's group, integrated into two real harnesses with several benchmarks; the benchmarks are partly the authors' choice. Weight: medium-high.

5. **[Context Is a Pipeline, Not a Window: Information Attrition in LLM Agent Harnesses](https://arxiv.org/abs/2610.36114)** (arXiv 2610.36114), plus [Hidden in Plain Sight: The Instruction Stacks of Coding Agents](https://arxiv.org/abs/2610.37332) (2610.37332), what the model saw isn't what the tool returned
   In a kernel-trace diagnosis agent that never used more than 5.75% of its window, a third of tool results (3,827 of 11,189) were cut by fixed-length JSON slicing, which always produced broken JSON. One field reached the model in 4.7% of calls while another reached it in 99.3%, and the cut showed up first as 43% more tool calls and twice the compute. Two of seven surveyed frameworks truncate the same unsafe way. The companion study captured the first model request from 1,886 releases of Claude Code, Codex, Gemini CLI, Qwen Code and OpenCode: tool definitions dominate three agents' requests, and only 48% of instruction-stack changes explain why they were made. For your harness: on every tool-result card, show "model saw N of M bytes" and which fields were dropped, and make the full instruction stack for a turn inspectable and diffable across versions. This complements the Oct 23 stale-instruction-file result (2610.30571). Credibility: medium for the attrition paper (one agent and domain; the authors say causation is still open); medium-high for the instruction-stack study (large longitudinal capture across five agents). Weight: medium-high.

6. **[ACP: let `cancelled` cover stops the user chose through the Agent (PR #2576)](https://github.com/agentclientprotocol/agent-client-protocol/pull/2576)**, plus [idempotent session/close #2575](https://github.com/agentclientprotocol/agent-client-protocol/pull/2575) and the open [v2 session lifecycle PR #2579](https://github.com/agentclientprotocol/agent-client-protocol/pull/2579)
   Merged this morning (about 5:10 AM PT):
   - **#2576:** yesterday's #2523 limited `cancelled` to `session/cancel` and closing. Now it also covers a user stop made through something the agent offers, such as answering a plan-approval request with "No, keep planning." Stops the agent makes for its own reasons still use `max_tokens`, `max_turn_requests`, `refusal` or `error`.
   - **#2575:** a second or racing `session/close` now SHOULD succeed, and clients treat `-32002` from close or delete as success.
   - **#2579 (open):** a session is active on a connection from new/resume until close or disconnect. Close doesn't delete. Re-resuming an active session re-syncs it. On disconnect the agent MAY continue or cancel foreground work and a later resume reports the outcome in its current-state snapshot.

   For your harness: a "keep planning" or "reject" button on a plan card is a user cancel, so label it that way rather than as a failure. After reconnecting, show "here's what happened while you were away" from the resume snapshot instead of assuming the run stopped. Credibility: high (primary spec changes by the maintainer; #2579 is still open). Weight: medium-high.

**Takeaway for a non-chat+diff harness:** Don't auto-restart on a stuck score. Show the alarm, the evidence and the remaining budget, and let continuation be the default. Give open-ended runs a stopping rule the agent doesn't own, and show churn. Make the subtask tree the main view and the source of context. Show what each tool result lost before the model saw it, and keep the instruction stack inspectable. Label user stops as cancels, and after reconnecting show what happened while the user was away.
