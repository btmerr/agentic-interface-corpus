# Agentic & AI interface brief — 2026-09-29

**Theme:** Judgment alignment over more checkpoints. Plans cut exposure; they do not certify runtime state. Scaffold re-entry (timing, interpretation, scope), make overrides durable protocol events, and turn finished traces into editable graphs you can reuse.

1. **[Comparing Human Oversight Strategies for Computer-Use Agents](https://arxiv.org/abs/2604.04918)** — Chen et al. (JHU / Notre Dame / Northeastern), CHI-class HCI study  
   Four strategies in one platform (Action Confirmation · Risk-Gated · Supervisory Co-Execution · Structurally Enriched). Plan-based strategies cut odds of problematic actions by 76%, but users blocked only 21% of actions that still reached execution—no strategy reliably improved intervention. Failures: mistimed authority, judging procedural correctness instead of content appropriateness, plan approval that reduces later scrutiny. Design for re-entry scaffolding, not denser approve buttons.

2. **[Human oversight of agentic systems in practice](https://arxiv.org/abs/2606.05391)** — Dhanorkar, Passi, Vorvoreanu (Microsoft), FAccT ’26  
   Interviews with 17 power-user developers. Oversight is four jobs: a priori control · co-planning · real-time monitoring · post hoc review—not just watching the stream. Real-time monitoring is rare; people satisfice with heuristics (plan as proxy for work, tests as correctness, eyeballing). Build surfaces for config + co-plan + review; stop assuming a continuous attention loop.

3. **[Collaborative Human-Agent Protocol (CHAP)](https://arxiv.org/abs/2606.09751)** — Shahid et al. / Brightbeam ([spec + TS/Python refs](https://github.com/BrightbeamAI/chap))  
   MCP = tools; A2A = agent↔agent; neither is the shared accountable workspace. CHAP Core (workspace, participants, tasks, artefacts, append-only evidence) plus Review/Modes/Handoff profiles. Overrides become typed diffs with rationale and content hashes—replayable years later. Complements yesterday’s A2UI: carry review packets as protocol events, not chat fossils.

4. **[A Deterministic Control Plane for LLM Coding Agents](https://arxiv.org/abs/2606.26924)** — Madatha (Rel(AI)Build)  
   Harness configs are unmanaged supply chain (10k-repo study: ~10% exact-dupe configs across orgs). Control plane above the harness: content-addressed agent defs, fail-closed permission tiers, attack-derived blocklists, phase state machine with AC→file→test trace, compile-once to seven IDEs. Deterministic gates, not another LLM governor. Pair with ASD “UI as security architecture.”

5. **[From Review to Reuse: Trace2Flow](https://arxiv.org/abs/2609.13136)** — Wu et al. (Saarland / Microsoft)  
   After the agent finishes, lift the trace into an editable n8n-style graph. N=20: validation success 65% with workflow vs 30% chat-only; cross-checking output + graph beats either alone. Follow-up reuse matched prompt adaptation on success/time. This is the “Update Assets” stage as a first-class surface—review object becomes reusable procedure.

6. **[Plover: Steering GUI Agents through Plan-Centric Interaction](https://arxiv.org/abs/2607.15193)** — Venkatesan et al. (UC Davis / Bosch)  
   Plans as persistent coordination objects with Intelligent Replanning (user-driven + system-driven). Multimodal annotation + plan edits + NL guidance; preserve executed history, revise pending suffix only. Of 26 autonomous OSWorld failures, 23 improved under plan-centric repair (~2 interventions/task). Complements Vibe-GUIDE: graph for orientation; Plover for localized repair mid-run.

**Takeaway for a non–chat+diff harness:** Prefer judgment-aligned re-entry over more gates. Separate plan-as-trajectory-constraint from runtime state verification. Persist overrides and handoffs as protocol (CHAP). Govern harness configs deterministically. After a run, promote the trace to an editable workflow graph—not another chat scrollback.
