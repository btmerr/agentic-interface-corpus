**Theme: What the agent was told, or says, isn't what's there.**

1. **[Stale Instruction Files Override the Code in Coding Agents: A One-Sentence Fix (arXiv 2610.30571)](https://arxiv.org/abs/2610.30571)**
   40 projects where CLAUDE.md/AGENTS.md conflicts with existing code: 90.1% of choices follow the stale file; Claude Code flagged the conflict in 79/80 runs and followed the file anyway; Codex CLI rewrote code to match in 20/80 (tests failed in 17). One user-level sentence giving code precedence flips code-following from 4.2% to 91.4%. Harness: instruction files arrive as instructions, code as tool output; surface instruction-vs-code conflicts as a decision, not a silent override. Companion: Governance That Scales with Capability (2610.31306) finds agent context files in 48.67% of top repos with 9.5-22% of named paths not resolving. Also: https://arxiv.org/abs/2610.31306. Credibility: medium. Two authors, 320 runs on synthetic projects; clear, falsifiable setup. Companion OSTEON paper is a position piece with no measured effect. Weight: high.

2. **[Atlas: Making Sense of Long Horizon Agent Trajectories (arXiv 2610.30548)](https://arxiv.org/abs/2610.30548)**
   Frames post-run sensemaking as goal/decision/artifact representation problem; trajectory tree shows what the agent chose and set aside, plus six artifact projections. N=14 within-subjects: higher decision transparency, lower workload. Harness: a returning user needs a branching decision map, not a transcript scroll. Credibility: medium-high. Ai2/UW HCI group (Weld, Downey, Zhang); small N=14 study, research-agent domain. Weight: high.

3. **[ProductWebBench: Evaluating Website Continuity Beyond Task Completion (arXiv 2610.31118)](https://arxiv.org/abs/2610.31118)**
   320 Change + 80 Build frontend tasks with staged requirements and checks that stay armed: 28.2% of runs passing every requested-work check still fail a continuity check; 10.8% re-break a state they had already passed; interaction fails in 29.5% of runs whose static DOM passes. Harness: show regression against previously verified states, with provenance, next to the requested-work checks. Credibility: medium. Large benchmark (8,737 runs, 13 models); frontend-only. Weight: medium.

4. **[ACP PR #2465: link session message views and keep identity off chunks (subagents RFD)](https://github.com/agentclientprotocol/agent-client-protocol/pull/2465)**
   Sender's outgoing and recipient's incoming session_message views now name each other (senderMessageId / recipientMessageId), optional and fillable in later chunks; identity kept off chunks. Lets a client jump between a parent's message and the subagent's view of it — the wiring for a fleet/subagent UI. Merged 2026-10-23, shipped in schema 1.13.0 release PR. Credibility: high. Primary protocol repo; merged by maintainer. Weight: medium-high.

5. **[Claude Code v2.1.309: 'outcome unknown' runner handoff + Changes pane scope labels](https://github.com/anthropics/claude-code/releases/tag/v2.1.309)**
   Self-hosted runner sessions that move to a new runner now show Claude the interrupted tool call marked outcome unknown; cloud Changes pane says when it lists only pushed commits or only Claude's edits. Also ctrl+o shows waiting inter-agent messages, /rewind attributes subagent/shell changes, many sandbox/permission hardenings. Harness: label partial views and unknown outcomes explicitly. Credibility: high. Primary release notes (2026-10-22 PT). Weight: medium.

6. **[Metacognitive Scaffolds Create Productive Friction for AI-Assisted Knowledge Work (arXiv 2610.30945)](https://arxiv.org/abs/2610.30945)**
   Randomized study (297 workers): goal-specification and decomposition scaffolds improve quality, persist after removal, improve recall — yet users rate the AI less helpful and more demanding. Harness: a plan/goal step can be worth it even when it tests worse on perceived ease; don't optimize friction away by satisfaction metrics alone. Credibility: medium-high. Microsoft Research Cambridge (Sellen, Sarkar, Rintel); writing task, not coding. Weight: medium.

7. **[Working Through Representation: Malleable Workspaces for Human-Agent Knowledge Work (arXiv 2610.30893)](https://arxiv.org/abs/2610.30893)**
   Conceptual model: humans and agents form and revise a Work Representation that drives action; 58-paper comparison finds most systems support incorporating agent output but few support reorganization or consequential agent-driven changes; 3-month study with 7 users. Harness: the workspace structure, not the chat log, should be the primary editable object. Credibility: medium. Conceptual analysis + small longitudinal study. Weight: medium.
