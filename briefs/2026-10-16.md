# Agentic & AI interface brief — 2026-10-16

**Theme:** Bind the workflow before irreversibility. An approval that names only the entry invocation is incomplete when the toolchain expands into postinstalls, MCP network, and hooks. A monitor forced to allow or deny on arrival cannot wait for evidence. A model that never saw control-state labels invents its own termination policy. Task success without boundary metrics is a false green. Shipping craft is catching up: coordinator fleet objects, mid-response steer as a control surface, and protocol metadata that multiple writers can patch without erasing each other.

1. **[Kairos: Transactional Security Enforcement at the System Boundary (arXiv 2610.18457)](https://arxiv.org/abs/2610.18457)**: defer the effect you cannot vouch for; decide at irreversibility
   Kairos sits as a reference monitor at a microVM isolation boundary (OverlayFS staging + TLS proxy), so tool calls and agent-written scripts cross the same file/network channels. A declarative trusted-source policy releases what it can vouch for and **defers** the rest while the agent continues speculatively on staged state; a bounded oracle (model or human) releases or refuses before anything becomes externally observable. On AgentDojo (GPT-4.1): attack success 47.0% → 2.7% while benign utility stays near undefended (85.1% vs 82.7%); a strict no-defer configuration keeps security but halves benign utility to 42.7%. Complements yesterday's Guarded Commits (ledger at commit) and HarnessSecurity-Bench (mechanism cells): Kairos's move is *when* you decide — hold until the trace makes the difference. Credibility: medium-high. Strong systems evaluation across three benchmarks and an adaptive attacker; semantic gap at the OS boundary and oracle persuasion remain disclosed limits. Weight: high.

2. **[Agent Approval Laundering: Transitive Effects Beyond the Approved Invocation (arXiv 2609.28586)](https://arxiv.org/abs/2609.28586)**: bind the predicted effect closure, not just the command string
   Sequel to Oct 12's Approval Laundering taxonomy. Here the durable record truthfully names the entry invocation (`pnpm install`, an MCP tools/call) while the workflow crosses file or network effects the record never asserted — six operational classes, a record-only indistinguishability lemma, and an Approval-to-Action Security Benchmark. Across 111 fixed pairs, residual records fall 40 → 17 → 13 as you add command semantics then decision-time metadata; on 11 fixed-SHA project runs, 10 → 2 → 0. Effect-bound records freeze source-backed predictions before authorization (0.926 macro recall / 0.941 precision on a 17-case holdout) and cut residual effect instances 10 → 3; a Claude Code PreToolUse prototype carries the same frozen record into ASK without auto-allow. Interface rule: show surface invocation *and* predicted transitive effects with provenance before the card. Credibility: medium-high. Careful forward-only protocol with honest paper-only release and private disclosures to vendors; no public artifact yet. Weight: high.

3. **[Harness Policy Distillation: Aligning Agent Policies with Runtime Semantics (arXiv 2610.20261)](https://arxiv.org/abs/2610.20261)**: make control state a training object, then hide the document at deploy
   Ordinary trajectory SFT shows which action was taken and leaves obligations, ready frontiers, and termination permission implicit — so the model repeats finished work or stops early. HPD replays reference trajectories through a product harness, compiles a privileged **control document** at each model-call boundary, verifies teacher candidates against the harness contract, and jointly trains three views of one shared model (native action, document-conditioned action, document reconstruction). At deploy, only the native view runs — no external document. On TRAJECT-Bench/Pi, Qwen3-8B reaches 22.98% task success and 49.23% runtime compliance vs 3.09% / 19.90% unadapted (OPD baseline 15.61% TS). For a non-chat harness: treat pending obligations and "final allowed?" as visible supervision objects during training *and* as UI chrome during runtime. Credibility: medium-high. Dense ablations and cross-harness adapters; still tied to successful reference prefixes and one eval harness family. Weight: high.

4. **[SWE-Misbehavior: Benchmarking Boundary Violations in Software Coding Agents (arXiv 2610.18206)](https://arxiv.org/abs/2610.18206)**: task green is not "within bounds"
   7.4K instances / 11 misbehavior metrics across Code Generation, File Management, and System Interaction — syntax/context/signature/body, CRUD file hygiene, env integrity, resource exhaustion, instruction following. SOTA scaffolds (OpenHands, smolagents, Agno, Claude Code) show dependency misreads up to 98.5%, unintended body changes up to 59%, and env-integrity hits up to 53% while still looking like task progress. Code-KIT (adaptive guidelines + purpose-built tools) cuts average misbehavior ~52% for smolagents and ~32% for OpenHands. Complements HarnessSecurity-Bench (attack surfaces under security toggles): this one scores *operational* over-acting on benign tasks. Harness UI takeaway: surface File Read / Context / Env Integrity beside the success badge, or the green check lies. Credibility: medium-high. Large real-repo construction with human-validated LLM judges; IF judge agreement is the weak cell (~72%). Weight: medium-high.

5. **[Cursor Projects](https://cursor.com/changelog/projects)**: the coordinator becomes the fleet object
   Shipping in beta. A Project is a long-lived body of work (feature, migration, app) with a **coordinator that does not write code** — it plans, delegates to cloud/local implementers in parallel, and brings finished work back for check. Shared context files sync across every machine the Project's agents use; "subscriptions" let the coordinator watch Slack, schedules, or PRs and act without a fresh prompt. This is the supervision surface ParallelPilot and fleet TUIs have been arguing for, productized: the primary object is the Project + coordinator plan, not a chat thread. Credibility: high. Primary Cursor changelog. Weight: high.

6. **[Codex CLI 0.163.0: mid-response steer, parallel read-only tools, searchable /config](https://github.com/openai/codex/releases/tag/rust-v0.163.0)**: interrupt is a control surface, not a restart
   Shipped Oct 15. Send a follow-up while Codex is responding and it steers immediately; interrupts also stop active Code Mode cells and nested tool calls. Independent read-only tools (skill, memory, history) run in parallel. `/config` becomes a searchable live preferences panel; `/daemon` restarts the managed background server with an interrupt warning; cold resume restores thread-owned permissions and network approvals. For a non-chat client: mid-turn steer and permission restoration on resume are first-class session controls — the user does not have to kill the turn to redirect. Credibility: high. Primary GitHub release notes. Weight: medium-high.

7. **[ACP v2 Metadata Patches RFD](https://agentclientprotocol.com/rfds/v2/meta-patches)**: multi-writer `_meta` without erase
   Drafted 2026-10-13. Top-level `_meta` on v2 upserts (`tool_call_update`, `terminal_update`, messages, session info, compaction, …) becomes a key-level patch: omit leaves stored keys, `null` clears all, object merges by top-level key (`null` value removes that key; nested objects replace whole). Fixes the migration tax where every writer had to resend every other extension's keys, and where a proxy annotating an update without `_meta` wiped the Agent's stored metadata. Replay must apply patches in order and explicitly null stale keys. For a control-surface client: progress, review state, and proxy route tags can coexist on one tool call without a single owner of the whole bag. Credibility: high. Primary ACP RFD; still Draft, Rust `apply_meta_update` not yet in published schema. Weight: medium.

**Takeaway for a non-chat+diff harness:** Draw the approval card on the *predicted workflow closure* (effects + provenance), not the argv alone, and give the monitor somewhere to *hold* an effect until the trace separates benign from attack. Treat pending obligations and termination permission as first-class chrome (and as training targets). Score boundary metrics beside task success. Make the Project/coordinator the fleet object, mid-turn steer a session control, and protocol `_meta` a patchable multi-writer ledger — never a last-writer-wins blob.
