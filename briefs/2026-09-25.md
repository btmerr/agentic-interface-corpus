# Agentic & AI interface brief — 2026-09-25

**Theme:** Supervision surface is the product. Chat is fine for intent; the harness UI is dashboard + gates + conflict panels + spatial pin-as-context, not a prettier transcript.

1. **Why AI Needs Control Surfaces, Not Just Chat** — https://cloudpresser.com/writing/why-ai-needs-control-surfaces  
   Staff-engineer stack: dashboard, task board, telemetry, reconciliation, intervention, notifications. Chat covers intent; everything after needs a control surface. Complements Blake Crosley’s Sep 7 supervision-surfaces piece with a sharper “operator interface” framing and a concrete `control-surface-agent` prototype.  
   *Credibility: High* (Luiz Ozorio, Staff AI Systems Engineer; Part 5 of a production-platform series) · *Weight: high*

2. **OrchVis: Hierarchical Multi-Agent Orchestration for Human Oversight** — https://arxiv.org/abs/2510.24937  
   GT HCI paper: goal hierarchy first (collapse tasks), orchestrator consolidates for the human, Planning Panel surfaces inter-agent conflicts with proposed repairs and predicted outcomes. Design goals map cleanly onto a non–chat+diff coding harness.  
   *Credibility: High* (Georgia Tech; arXiv Oct 2025; cites Magentic-One / Cocoa / CHI steering work) · *Weight: high*

3. **Designing Oversight UI for AI Agents (HITL vs HOTL)** — https://edgar.design/blog/designing-oversight-ui-for-ai-agents-dashboards-escalation-and-control-boundaries  
   Decision matrix (stakes × reversibility → gate vs supervise), five anti–automation-bias patterns (surface uncertainty as layout, force articulation at high-stakes gates, separate generated vs grounded, cheap undo, log reasoning), four architecture commitments (capability tiers at API, sandboxes, reversibility windows, self-instrumentation). EU AI Act Article 14 as floor, not the design.  
   *Credibility: High* (practitioner UX essay with copyable matrix/checklist; rooted in clinical automation-bias literature) · *Weight: high*

4. **Grasp** — https://github.com/cocofhu/grasp · https://www.approving-ai.com/  
   Visual FSM canvas (when-guards, checkpoints, rollback), unified human-gate Inbox across parallel runs, Docker sandboxes over ACP, artifact MCP contract. Multi-backend (Cursor / Claude Code / CodeBuddy / Trae). Shipping craft for “approve at critical nodes,” not chat-modal Plan Mode.  
   *Credibility: Medium-high* (~395★ OSS, active Sep 2026, CI + sandbox gateway in-repo) · *Weight: high*

5. **plan-review-hub** — https://github.com/abassaf/plan-review-hub  
   Provider-agnostic skill: serve plans on a local LAN hub, collect verdict + decision answers + notes, then dispatch approved plans to isolated git worktrees. Findings audits (cross-file bug → Fixed/Fine badges) sit beside plans. Plan as reviewable web object with structured feedback, zero npm/pip deps.  
   *Credibility: Medium* (new skill, low stars; unusually sharp “plan → hub → worktree” loop) · *Weight: medium-high*

6. **pmx-canvas** — https://github.com/pskoett/pmx-canvas  
   Moldable infinite board where spatial pin/group/proximity becomes agent context via `canvas://pinned-context`. Agents stream panels onto the board mid-session; humans curate focus. Complements OpenCove/ccanvas: arrangement is the protocol, not decoration.  
   *Credibility: Medium-high* (public OSS with explicit product vision + Copilot/Codex host integrations) · *Weight: medium-high*

7. **ACP UI** — https://github.com/formulahendry/acp-ui · https://acp-ui.github.io/  
   Cross-platform Agent Client Protocol client (desktop/mobile/web): sessions, permission prompts, session modes, traffic monitor for live ACP messages. Harness shells should speak ACP rather than one-vendor SDKs; this is the reference multi-surface client.  
   *Credibility: Medium-high* (~485★; tracks official ACP agent registry) · *Weight: medium*
