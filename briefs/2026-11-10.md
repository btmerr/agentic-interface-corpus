# Agentic & AI interface brief — 2026-11-10

**Theme: What you checked isn't what can hurt you.** Developers review the diff but wave through the actions. Test suites pass while a removed restriction goes unnoticed. Agents say "done" on work that's wrong, and harnesses report "clean," "succeeded," or "stopped by user" when none of that is true. For a non-chat harness, the review surface has to cover actions and permissions, not just code, and every status the UI shows needs to come from a measurement.

1. **[From Delegation to Action Approval: An Exploratory Study of Developers' Practices in Collaborating with AI Coding Agents](https://arxiv.org/abs/2611.10058)** (arXiv 2611.10058), careful code reviewers still rubber-stamp actions
   A survey of 203 developers who use coding agents found that 61% of those who carefully review most or all generated code still often approve at least one type of agent action (shell commands, file reads) without looking closely. Developers who knew about security incidents did this *more* often, not less. Autonomy varied more between people than between tasks, and supervising stayed mentally demanding even though workload felt lighter. Asked what would earn more autonomy, more than half asked for agents that are bounded, observable, or reversible, not just more reliable. That's a direct spec for your approval surface: show what an action can touch and how to undo it, and make per-person autonomy settings first-class. Credibility: medium-high (established SE researchers incl. Kathryn Stolee and Bowen Xu; self-reported survey, so it captures habits, not observed behavior). Weight: high.

2. **[Mutation Testing for Multi-Agent Workflows](https://arxiv.org/abs/2611.09895)** (arXiv 2611.09895), task-success tests catch about half of permission violations
   Fourteen mutation operators perturb a multi-agent workflow (dropped delegation, removed restriction, misrouted tool, faulty tool), run across ten OpenAI Agents SDK workflows and 29,601 agent runs. The best baseline suite catches 0.72 of structural faults but only 0.56 of safety faults, and a silently removed restriction is the least-detected fault (0.19 to 0.28). Pairs with yesterday's guardrail-drift item: a harness that edits tool rules or delegation needs its own regression check on what's forbidden, not just "did the task still succeed." Credibility: medium-high (large execution count, k=3 repeats with majority vote; single SDK; affiliations not checked). Weight: high.

3. **[Done Is Not Correct: Measuring Silent Failures and Self-Verification Calibration When LLM Agents Take CAD Actions](https://arxiv.org/abs/2611.10063)** (arXiv 2611.10063), a measure-then-claim contract beats extra agents
   Single-shot agents claimed completion on 98% of attempts and were silently wrong 14.1% of the time. A loop that forces the agent to measure before it claims cut silent failures to 3.2% and raised claim precision from 64% to 96%. A four-model ablation credits the claim contract, not the feedback, and a planner-coder-checker pipeline matched precision with no success gain. CAD is the domain, but the lesson carries over: make "done" a gated state that requires attached evidence. Complements the Nov 3 RECEIPT and Oct 30 Soei claim-vs-proof items with a cleaner causal result. Credibility: medium (small benchmark of 13 tasks; strong self-audit of its own grader; benchmark and attempt records released). Weight: medium-high.

4. **[Claude Code v2.1.321](https://github.com/anthropics/claude-code/releases/tag/v2.1.321)**, a release that's mostly about honest state
   Fixes worth copying as test cases: a read-only Bash command ran outside the sandbox with no prompt; deny rules and protected-file prompts didn't apply to the file a `cp` or `mv` into a directory writes; `NotebookEdit` reported success to hooks and telemetry when the edit failed; background agents were reported as "stopped by the user" (and refused a resume) when a service interrupted the session; the startup git status read as clean when `git status` failed (now "unavailable"); and a "Queue for later" message reached Claude mid-turn. Also adds `--settings <file>` to `claude remote-control`, applied to every session it starts. Each is a status the UI showed that the system hadn't earned. Credibility: high (official release notes). Weight: high.

5. **ACP [#2786](https://github.com/agentclientprotocol/agent-client-protocol/pull/2786) / [#2787](https://github.com/agentclientprotocol/agent-client-protocol/pull/2787) / [#2788](https://github.com/agentclientprotocol/agent-client-protocol/pull/2788)**, protocol rules for background work, subagent references, and plans
   Three merges from yesterday. Background work with no tool call of its own (hook-started tasks, MCP tasks) gets an agent-started tool call; final statuses stay final, and work that continues gets a *new* call instead of reopening an old one. A new `session` tool-call content type lets a tool call point at a subagent session for display only; it explicitly doesn't grant controls or report work state, and one-shot children are allowed. Plan semantics are pinned down because Zed, the Claude adapter, and the Codex adapter had each done something different: a `plan_update` replaces the whole plan, cancelled plans SHOULD send `plan_removed`, and clients ignore removals for unknown plans. If your harness speaks ACP, these settle your plan panel and background-tasks list. Credibility: high (maintainer benbrandt merges; unstable/draft docs and RFDs, not yet stable). Weight: high.

6. **[WorkflowArena: Benchmarking Executable Workflow Orchestration in LLM-Based Multi-Agent Systems](https://arxiv.org/abs/2611.12856)** (arXiv 2611.12856) + **[Unprompted coordination through shared memory in LLM agents](https://arxiv.org/abs/2611.12412)** (arXiv 2611.12412), the model now designs the org chart
   WorkflowArena has 145 long-horizon tasks across 8 domains where the agent decides whether and how to delegate, with every delegation recorded. No configuration wins everywhere, and harnesses differ in style: at high effort, Claude models in Claude Code launch workflows less often but with bigger worker groups, while GPT models in Codex delegate more often in smaller units. Your fleet view should show the delegation structure the model chose, not just the workers. The companion study found agents coordinated through a shared key-value store with no prompt mentioning partners, and one sentence ("check your workspace again before submitting") switched it on and off, so shared state between agents is a channel that should be namespaced and logged. Credibility: medium (WorkflowArena: new benchmark with a hidden verifier, affiliations not checked; coordination study: small toy task but independently re-implemented under pre-locked designs). Weight: medium.

7. **[SPRING-5: Measuring Tool Documentation Repair for LLM Agents by Efficiency](https://arxiv.org/abs/2611.10040)** (arXiv 2611.10040), most wrong answers leave no trace
   Across 2,644 sessions with degraded tool specs, 54% of wrong answers arrived with no rejected call, no refusal, and no retry, so the trace looks clean. Two runs on a byte-identical spec differed by a factor of 0.64 to 1.56, meaning about one comparison in eight crosses a typical win threshold on noise alone. Two lessons for a harness: a quiet trace isn't evidence of success, and any A/B of tool descriptions or prompts needs a measured noise floor. Credibility: medium (single author; careful validity checks; code, data, and runs released). Weight: medium.

**Also noted, complementing earlier items:** [Replay Fidelity in LLM Agent Evaluation](https://arxiv.org/abs/2611.11216) (arXiv 2611.11216) extends the Nov 6 fork-safety item: matching outputs and verdicts still hid different database row effects on replay. [Linking Event-sequence Data Claims to Analytic Provenance in Chatbots](https://arxiv.org/abs/2611.11325) (arXiv 2611.11325) shows claims cited to addressable cells of an analysis table made people trust correct claims more and wrong ones less, a pattern worth borrowing for agent reports. [Feeling Easier, Working Harder](https://arxiv.org/abs/2611.12019) (arXiv 2611.12019) found AI help raised measured cognitive load 11.2% while perceived load stayed flat (20 novice students, so treat as a signal).

**Takeaway for a non-chat+diff harness:** Put actions and permission changes on the review surface with their reach and undo path. Regression-test what's forbidden, not just what succeeds. Gate "done" on attached evidence. Treat every status (clean, succeeded, stopped by user) as a claim the system has to back, and show the delegation structure the model chose.
