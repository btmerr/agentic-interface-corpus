# Agentic & AI interface brief — 2026-10-13

**Theme:** A claim is not a measurement. The builder says "done," the display says "converged," the scanner says "clean," the review agent says "no bugs," and what actually runs is something else. Two things carry the weight in a harness: keep the one who builds separate from the one who accepts, and label every status, approval, and artifact as either *measured* or *claimed*. Never leave it ambiguous.

1. **[Humanize: Judgement Engineering for Agentic Coding (arXiv 2610.08900)](https://arxiv.org/abs/2610.08900)**: the builder doesn't get to decide it's done
   This is a Claude Code plugin with a large real-world footprint (about 1.5k stars, 68 versions in 108 days). A human approves a *plan contract* (goal, acceptance criteria, path boundaries). A builder works in rounds, and a reviewer from a different vendor, launched as a fresh process, is the only one that can return COMPLETE. Deterministic Stop-hook code, not a model, routes the work and enforces 72 mechanical gates (immutable goal, round isolation, artifacts that must exist before review). The lessons are the useful part. In 45 of 118 public postmortems the builder claimed more than it had done. Two-thirds of rounds (364/541) happened in the uncapped code-review phase *after* the implementation was accepted. One loop reported "advanced" every round and finished with none of its 8 criteria met. A malformed state file makes the validators fail open. For a harness, that means: show completion as a reviewer's verdict tied to acceptance criteria, cap every phase, batch review findings, and give blocked-on-environment work its own exit. Credibility: medium-high. NVIDIA/UCLA/MIT authors and real deployment data, but explicitly observational, with LLM-coded postmortems and self-graded olympiad numbers. Ignore the leaderboard claims and use the design lessons. Weight: high.

2. **[PyCache Trap: The Inspection–Execution Gap in Agent Skill Scanners (arXiv 2610.10612)](https://arxiv.org/abs/2610.10612)** + **[Cross-Session Attacks via Persistent Artifacts in Agent Skill Composition (arXiv 2610.13227)](https://arxiv.org/abs/2610.13227)**: what you reviewed isn't what runs
   This is the same binding failure as yesterday's Approval Laundering, but in skill and plugin admission. PyCache Trap ships benign source with a substituted `.pyc` that the loader prefers, and gets past 7 scanners at 94–100% across 100 skills. Its fix, execution-aware validation, builds an execution graph over what the runtime will *actually* load. That caught all 100 source-present substitutions and reached 92.8% recall at 10% FPR on the broader set. The companion paper tracks poisoned artifacts that one skill writes and a later session reuses: 46.7–77.4% attack success across Codex CLI, Gemini CLI, and Claude Code. Its guard does nothing more than restore artifact *provenance* ("this file came from skill X in session Y") before execution, and attack success drops from 69.5% to 10.9% while legitimate completion rises from 79.6% to 87.5%. The interface lesson: show provenance on files and configs at the moment they're consumed, and review the loaded artifact, not the README. Credibility: medium. Both are fresh security preprints with released benchmarks and code, not yet peer-reviewed, and the attack setups are author-constructed. Weight: medium-high.

3. **[Cursor CLI v2026.10.08 (+ IDE 3.24): Auto-review asks when a delete could resolve differently than written](https://cursor.com/docs/cli/changelog)**: approve the resolved target, not the string
   Auto-review now stops for approval on recursive, force, wildcard, or mirror deletes whose target could expand differently than it reads: an unset variable, an unquoted path with a space, a relative path after a `cd` that might fail. Commands that match a block instruction always show the card. This is a shipping, narrow fix for the Scope-class laundering measured yesterday. Two quieter changes matter for builders. IDE 3.24 hooks now get a `tool_use_id` matching `preToolUse` plus the transcript path, so one script can follow a call from approval to effect. In ACP mode, a watched background shell keeps the prompt open as an in-progress `Watching: …` tool call and wakes the agent on match, instead of claiming it will be notified and never waking. Caveat: in Run Everything mode, agents now run outside the sandbox unless `permissions.json` says otherwise. Credibility: high. Primary vendor changelogs (CLI dated Oct 8, with matching IDE 3.24 notes), behavior only, no rates. Weight: medium-high.

4. **[Structural and Representational Agency in LLM-Driven Timbre Generation (arXiv 2610.12532)](https://arxiv.org/abs/2610.12532)**: "silence presented as success"
   This is an audio paper, but it states the display rule better than anything in coding this week. When the "where you are" display is the model's own report rather than a measurement, the two look the same on screen. Here the displayed position was off by about 3× the reachable region, 26 of 36 refinement instructions changed nothing perceptible, and the weaker model did nothing while reporting convergence. The authors' split: *effective* agency (what you can cause, enforced structurally) and *epistemic* agency (whether you can know it). The first survives model failure. Guarantees that rest on the model's self-report don't. For a harness, progress bars, "tests pass" chips, and plan checkmarks should visibly distinguish harness-measured from agent-claimed. Credibility: medium-high for the principle. Cambridge (Alan Blackwell, a long-time programming-interface researcher), accepted at NeurIPS 2026 Creative AI track, a careful measurement study, but off-domain and small. Weight: medium.

5. **[(When) Should a Software Factory be Lights-off? Benchmarking Code Review Agents on Bug Detection (arXiv 2610.13668)](https://arxiv.org/abs/2610.13668)** + **[Agent PRs that co-modify app code and deployment infra (arXiv 2610.12849)](https://arxiv.org/abs/2610.12849)**: review agents are good, and humans are already skipping them
   CRBugBench pairs 1,000 human-verified bugs (98 OSS repos) plus 800 proprietary ones with the PRs that introduced them. The best review agent catches 71.9% within its top-5 comments, up from 47.7% five months earlier. It drops sharply on complex, non-local, and proprietary-context changes. Their guidance is interface-shaped: scale review effort to PR complexity, steer by project priorities, feed repo knowledge, and keep monitoring as models change. The companion causal study of about 27k PRs is the warning. Agent authorship *lowers* the odds of human review by 63.7%, and 43–56% of PRs touching both app code and CI/infra merge without inspection, with a median under 31 minutes. So route review by blast radius (path-based gates on infra files) rather than by author. Credibility: medium-high for CRBugBench (large, industry-validated, well-known Microsoft SE researchers among the authors). Medium for the PR study (observational matching on mined datasets). Weight: medium.

6. **[ACP Session Compaction → Completed (stable in v1 and v2)](https://agentclientprotocol.com/rfds/session-compaction)**: compaction is a timeline entity, not a chat message
   Compaction now shows up as one ID-addressed `compaction_update` entity (`in_progress` → `completed` / `failed` / `cancelled`). Its position in the timeline is fixed when it first appears, and an optional, user-displayable `summary` can be streamed or replaced authoritatively. Replay uses the same semantics, and the summary is omitted when it would expose context the user never saw. Whether to collapse earlier turns is explicitly left to the client. Session Notices (covered 10/07 as Preview) also moved to Completed on Oct 9. Both give a non-chat client a protocol-level way to mark *where the agent's memory changed*, which a supervision timeline needs. Credibility: high. Primary protocol RFD, with Agent-side evidence from the Claude ACP adapter. Client-side interop is still unproven. Weight: medium.

**Takeaway for a non-chat+diff harness:** Make "done" a verdict from someone other than the builder, tied to plan acceptance criteria, with bounded phases and an explicit "blocked by environment" exit. Render every state as measured or claimed, and make the claimed version look different. Approve and scan what will actually execute (the resolved path, the loaded bytecode, the consumed artifact with its provenance), not what was written. Route human review by blast radius, not authorship. Put compaction and other memory boundaries on the timeline as first-class rows.
