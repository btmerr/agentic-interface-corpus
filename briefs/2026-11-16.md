# Agentic & AI interface brief — 2026-11-16

**Theme: Every handoff loses evidence, and the system ends up as safe as whoever saw the least.** A strong orchestrator that reads a forged file itself almost never acts on it, but once it delegates the reading to a cheaper subagent, the whole system fails at the subagent's rate. A verifier's correct verdict flips about 31% of the time when it sees the same run through a delegation or compaction boundary, and restoring provenance recovers most of those flips. An agent that's told "there's one more match" acts anyway, while one that's shown both matches stops. A production-debugging agent that confidently shipped wrong fixes wasn't making things up; it simply couldn't see the lock state. For a non-chat harness, the job is to carry evidence across every boundary (subagent, compaction, tool summary, lookup) and show the supervisor what each actor could actually see.

1. **[Only as Safe as the Weakest Agent: A Break That Appears Only When the System Is Multi-Agent](https://arxiv.org/abs/2611.17520)** (arXiv 2611.17520), delegation brings safety down to the reader's level
   Agents answer questions from a file store that contains one planted forged record. Strong orchestrators that search the store themselves made almost no harmful revisions in more than 1,000 trials. When the same orchestrator delegates to a cheaper subagent, as Claude Code, Codex, and a reference harness are built to do (all unmodified), failures rise to 20/180, 44/180, 75/180, and 553/900. In simulations over 18 models, aggregators that were almost never unsafe on their own repeated a corrupted subagent's error in 751/757 trials. For your fleet and subagent views: show which model *read* each source, mark claims that came only from a weaker reader, and let the orchestrator (or you) re-read the cited source before a write. Extends the Nov 9 subagent-attribution work. Credibility: medium-high (real unmodified harnesses, large trial counts; single attack family, forged-record setting). Weight: high.

2. **[Do Verifier Judgments Survive Abstraction? Measuring Verification Transport](https://arxiv.org/abs/2611.18471)** (arXiv 2611.18471), the same run looks different to a judge after a boundary
   The authors froze executions and showed verifiers native, abstracted (composed tools, delegation, compacted history), and restored views, keeping the task, trajectory, outcome, and criterion fixed. Across 4 benchmarks, 7 verifier backbones, and 4 protocols, judgments changed under abstraction up to about 31% of the time with macro-abstraction plus delegation. Direct verification more often gives a wrong verdict, while evidence-grounded protocols tend to abstain, so a lower flip rate doesn't mean better reliability. Restoring execution provenance recovers 85.5% of the failures, less when provenance is lossy. This directly follows Friday's write-check-vs-judge and Cleaning History items. Show each verdict with *which view* the judge saw, treat "abstained: not enough visible evidence" as its own state, and keep provenance handles across compaction (as Folio does). Credibility: medium-high (careful matched-view design, broad backbone/protocol grid). Weight: high.

3. **[What LLM Agents See and What Users Say](https://arxiv.org/abs/2611.17639)** (arXiv 2611.17639), lookups should list competing matches, not count them
   Before an irreversible act, each assumption behind it (for example "one reservation matches this name") should be *seen*, *answered by the user*, or *disclosed while still undoable*. Across 36 agents, a search that only *counted* a second match left most of them acting on the one record they saw; *listing* both stopped most of them. The newest Claude and GPT models always opened the counted record and then didn't act. Adding a same-name, same-zip customer to a retail benchmark led to wrong-account writes in about a quarter of conversations. A lookup that checks a detail only the user knows (the street) kept completion near baseline. Design cue: your approval card for a destructive action should list the assumptions behind it, each tagged seen / user-stated / undoable, and tool results should list ambiguous matches instead of summarizing them. Credibility: medium-high (formal framing, 36 agents, benchmark perturbation). Weight: high.

4. **ACP: [Session cursors RFD merged (#2114)](https://github.com/agentclientprotocol/agent-client-protocol/pull/2114) + [Agent Skills RFD (#2818)](https://github.com/agentclientprotocol/agent-client-protocol/pull/2818) and [v2 schema (#2822)](https://github.com/agentclientprotocol/agent-client-protocol/pull/2822) + [prompt suggestions (#2404](https://github.com/agentclientprotocol/agent-client-protocol/pull/2404)/[#2821)](https://github.com/agentclientprotocol/agent-client-protocol/pull/2821)**, addressable positions, typed skills, and suggestions that never send themselves
   The session cursors RFD merged this morning. A cursor is an opaque `cursorId`, announced by a `cursor_update`, with a fixed anchor before or after a message, tool call, or **compaction**, plus capabilities that say which methods accept it. `session/fork` gets an optional `cursorId`, so forking from any point (including "just before that compaction") becomes a wire operation. Open questions remain: partial replay, and whether v1 anchors for live prompts are workable. Agent Skills (draft RFD, now in the v2 schema behind `unstable_agent_skills`) adds a typed `skill` command entry with the `SKILL.md` path and a `skill` content block. It has two agent capability levels because Claude Code runs only one skill at the start of a prompt while Codex and OpenCode take several anywhere, and it hasn't been tested against the adapters yet. Prompt suggestions (merged and implemented behind a flag): accepting one **fills the composer and must not send it**, a suggestion from before your last prompt is never offered, and suggestions stay out of replay. For your timeline: cursors give you real "branch from here" handles, skills become a first-class palette item with a source path, and suggestions get a rule worth copying (the user stays the author). Credibility: high (official repo, maintainer-merged; skills not yet validated against adapters). Weight: high.

5. **[Claude Code v2.1.325](https://github.com/anthropics/claude-code/releases/tag/v2.1.325)**, more "say what's actually true" and tighter unattended defaults
   Copyable details: an approved plan edit that can't be written to `plansDirectory` is now saved to the default folder *with a warning saying where and why*, not lost. `/model` no longer says your org restricts a model when it couldn't check. `/insights` no longer says a report is ready when nothing qualified. Recent turns no longer go missing on resume after an unclean exit. Sessions no longer show "waiting for input" when a finished PR only needed your own review. Moves to another sign-in in the background are refused with a message. Defaults move toward asking: sandboxed Bash now goes through the normal permission flow unless you opt out, scheduled tasks and `/loop` ask before running a skill that declares tools or hooks, and Esc on a background MCP task's question means "answer later" (the question stays in `/tasks`). VS Code gets Tab-to-accept prompt suggestions, the shipping version of item 4. Takeaway: "couldn't check" and "saved elsewhere, here's why" are their own states, and unattended runs should lean toward waiting for you. Credibility: high (official release notes; not independently tested). Weight: medium-high.

6. **[Where LLM Agents Get Stuck Debugging Databases: Access More Than Reasoning](https://arxiv.org/abs/2611.17304)** (arXiv 2611.17304), wrong-but-consistent hypotheses come from missing access
   A field report of Claude Code diagnosing eight incidents in a production message-dispatch engine. In every concurrency-dependent incident, the agent announced a cause, shipped a fix, and later walked it back, and each wrong guess cost a deploy-and-observe cycle. In all five, the gap included access to production state: live lock views, untruncated deadlock reports, read-only execution, and explicit environment context. The wrong hypotheses *matched the evidence the agent could see*; they weren't fabrications. The proposed fix is a forensics layer with a safe interrogation API, a lock/deadlock flight recorder, and a replay harness. For your harness, this argues for a "what the agent can't see" panel next to each diagnosis, and for read-only production probes as a first-class tool rather than ad-hoc shell. Credibility: medium (n=8 incidents, one system, one agent, qualitative, but real production). Weight: medium.

**Also noted:** [CarryOn](https://arxiv.org/abs/2611.17808) (arXiv 2611.17808) keeps a compact execution state paired with source-linked evidence, chosen by a learned selector with no extra LLM calls, and gets +6.7 pts over the best baseline on AppWorld, OfficeBench, and Tau2. It's another vote for compaction with handles. [isloss](https://arxiv.org/abs/2611.15543) (arXiv 2611.15543): 18.5% of translated requests pass target checks while silently changing prompt, role, or tool info, which matters if your harness bridges providers or ACP adapters. [HerAgent](https://arxiv.org/abs/2611.18443) (arXiv 2611.18443) uses semantic "setup blocks" as one unit for execution, validation, checkpoint, and rollback (SetupBench 46→70%), a good granularity for a rollback UI. [Interpreting Coding Agents Through Behavioral Trajectories](https://arxiv.org/abs/2611.17440) (arXiv 2611.17440) maps 143K trajectories to search/edit/test actions with a released deterministic parser; agents with equal solve rates behave very differently, so it's useful as a per-run behavior strip.

**Takeaway for a non-chat+diff harness:** Track *who saw what*. Attribute every claim to the actor that read its source, show every verdict with the view it was based on, and list ambiguous matches instead of counting them. Make positions in a session addressable so "fork from before that compaction" or "before that subagent's summary" is one click. Give "couldn't check," "not enough visible evidence," and "can't see production state" their own visible states.
