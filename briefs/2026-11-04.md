# Agentic & AI interface brief — 2026-11-04

**Theme: A result is only as good as the record behind it.** Today's items all point at the same gap: users see an outcome, but not the forks the agent took, the checks that ran, or the failures that got dropped. Traces you can fork from, maps of paths not taken, failed turns that stay in history, and graders that report what they actually scored are the pieces a non-chat harness can build its surface around.

1. **[From Watching to Steering: Enabling Human-Coding Agent Collaboration through Execution Traces](https://arxiv.org/abs/2611.04466)** (arXiv 2611.04466), fork from a good step instead of restarting
   Vibetrace, built on OpenCode, shows an agent's run as an interactive execution trace of actions, intermediate states and failures. The user can fork execution from an earlier step and give a targeted correction without throwing away work that was already validated, and traces plus human feedback get distilled into reusable skills. On SWE-bench Verified the distilled skills cut input tokens 23.0% and cost 15.5% and moved pass rate from 65.0% to 68.0%; their user study reports better accuracy and speed than reading logs. For your harness: this is close to the core non-chat interaction, the trace as the main object, with "fork from here with a correction" as the primary steering verb. Credibility: medium (five authors, real harness, modest benchmark gain; user-study size not stated in the abstract). Weight: high. Builds on Nov 2's ReplayRCA live-vs-post-hoc oversight (2610.41025).

2. **[Agentic Path Maps: Exposing an Agent's Traversal Through the Garden of Forking Paths](https://arxiv.org/abs/2611.04183)** (arXiv 2611.04183), show the choices the agent didn't take
   Asking the user about every judgment call is untenable, so the authors look at showing impactful unexplored paths after the run. They lay out a design space for presenting alternatives and test one dimension, how many alternatives to show, in a 48-person study on data-analysis tasks. People rarely considered alternatives on their own, but overreliance on the AI dropped when the alternatives were drawn for them. For your harness: after a run, surface the two or three decisions that most shaped the result with the road not taken, as a cheaper alternative to more mid-run questions. Credibility: medium (eight authors, n=48, data analysis rather than coding). Weight: high. Complements Nov 2's When Should AI Agents Ask? (2610.41129): that's when to interrupt, this is what to show instead of interrupting.

3. **[A Gated Spec-Driven Workflow: An Audit-Trail Study of Coding-Agent Work](https://arxiv.org/abs/2611.05094)** (arXiv 2611.05094), the orchestrator grading its own checks is the weak spot
   A spec-driven Claude Code workflow: the user approves each stage, a reviewer subagent checks artifacts against a fixed defect list, executors may only touch files listed in their task, and a file-inventory check runs after each block. Across nine features in seven projects (581 planned tasks, 288 done block by block), executors mostly stayed in scope, with one undeclared change that the check caught. The orchestrator, which runs and judges its own checks, recorded undeclared changes in 11 of 247 block checks and stopped work in only four. For your harness: per-task file scopes work, but enforcement and the stop decision belong in the harness, not in the same model that's being constrained. Credibility: low-medium (two authors, all runs by the authors, honest about protocol departures). Weight: medium-high. Pairs with Nov 3's Boundary Contracts (2611.01265).

4. **[Silent Instrument Errors Reorder Agent Leaderboards](https://arxiv.org/abs/2611.04399)** (arXiv 2611.04399), the grader is part of the measurement
   Auditing HAL and tau2-bench from published artifacts: a 13-point gap between a general agent and a specialized scaffold came from the general agent's episodes often never triggering grading, so only about half were scored and the rest counted as failures. Other errors: a cost column double-counting nested model calls, grader-written actions recorded as agent actions, and a mode check that misread four files and collapsed their scores by 59 to 82 points with no error printed. HAL maintainers confirmed their three within five weeks. Proposed checks: report the graded fraction, aggregate cost from root spans, tag the provenance of every recorded action, and pin evaluator versions with a re-grade diff. For your harness: the same applies to your own run history and dashboards, so tag who wrote each action and show what fraction of runs were actually checked. Credibility: medium-high (single author, but maintainer-confirmed and reproduction code released). Weight: medium.

5. **[MCPGuard: Finding Conformance Gaps in MCP SDKs via Dual-Track Analysis and Dynamic Adjudication](https://arxiv.org/abs/2611.03662)** (arXiv 2611.03662), the official SDKs don't enforce the whole spec
   Compares the MCP spec's schema constraints and prose rules against the official SDK code, then builds proofs of concept to confirm. It confirmed 13 gaps in the Python SDK 1.26.0 and 19 in the TypeScript SDK 1.29.0, none caught by two black-box baselines, and shows they carry through to open MCP servers. For your harness: don't assume a server built on the official SDK validates what the spec says it must; validate on the host side. Credibility: medium (six authors, confirmed findings with PoCs; the specific gaps aren't listed in the abstract). Weight: medium. Complements Nov 3's When Neither Side Confirms (2611.02527).

6. **[Do Coding Agents Follow AGENTS.md? The Effect of Policy Wording on Instruction Compliance](https://arxiv.org/abs/2611.04367)** (arXiv 2611.04367), "if X then Y" gets followed less
   One policy inserted in four wording styles into the agent context files of 86 benchmark tasks, across four harness-model combinations. Conditional phrasing was followed less often than prescriptive or explanatory phrasing, and which of those two did best depended on the combination. For your harness: when you generate or lint AGENTS.md-style rules, rewrite conditionals as direct rules, and don't expect one wording to win across models. Credibility: low-medium (four-page short paper under review). Weight: medium. Adds to Oct 23's Stale Instruction Files (2610.30571) and Nov 3's ARCBench (2611.03223).

7. **[Claude Code v2.1.318](https://github.com/anthropics/claude-code/releases/tag/v2.1.318)**, plus [ACP RFD #2756: failure entries in session history](https://github.com/agentclientprotocol/agent-client-protocol/pull/2756), keep the failure on the record
   Released Nov 3 (about 4:01 PM PT). Highlights:
   - Permission prompts are no longer answered by keys typed just after sending a message or before a slow prompt appeared.
   - A shell command approved after a cloud or self-hosted restart now runs in the folder it was asked in, or not at all.
   - Logout, MCP removal and trust or consent changes no longer report success when the config file couldn't be written.
   - Headless runs no longer report success when an API error cut off a reply, and idle compaction no longer replaces a conversation with something that isn't a summary.
   - The answer you gave when Claude Code asked to turn on mods it wrote is now recorded.

   ACP #2756 (draft RFD, opened Nov 3 about 8:53 AM PT) adds a `failure` session update with its own ID and position that is replayed on resume, so a failed, truncated or refused turn doesn't vanish on reload and leave the user's message unanswered. It builds on yesterday's #2755 error classification. Related: [#2753](https://github.com/agentclientprotocol/agent-client-protocol/pull/2753) proposes reading a session's text without activating it. For your harness: a prompt should only accept input meant for it, an approval should run exactly what was approved, and failures belong in the timeline as first-class entries. Credibility: high for the release notes (primary); the RFDs are open proposals only. Weight: medium.

**Takeaway for a non-chat+diff harness:** Make the trace the main surface, with fork-and-correct as the steering verb. After a run, show the few forks that mattered. Enforce scopes and stop decisions in the harness, not the model. Keep failures and provenance in the record, and say what fraction of work was actually checked.
