# Agentic & AI interface brief — 2026-11-05

**Theme: What the harness claims must match what it actually did.** Today's items all put the harness under a verification lens: every tool call needs a declared intent checked against observed effects, a signed MCP server can still leak through an allowed destination, and a harness optimized for one task type can quietly forget how to do another. For a non-chat control surface, that means intent, effects, and retention belong in the record as first-class objects — not as vibes in the transcript.

1. **[Episteme: Trustworthy Coding Agents Through Tool Call Intent](https://arxiv.org/abs/2611.06563)** (arXiv 2611.06563), every tool call carries a typed why the harness can check
   Coding agents mutate state through tool calls, but the call never says why. Episteme makes the harness refuse any shell command that lacks a closed-vocabulary type (collect-info, test-hypothesis, verify, setup, change-state, revert, cleanup) plus a free-text reason, then records effects (file diffs, HEAD moves) and checks the declaration against them. Online, a read-only declaration whose command text looks mutating can be refused; offline, the journal is forensics the model cannot rewrite. On ImpossibleBench (tasks that can only be "passed" by cheating), the journal exposed 44 of 49 reward-hacking runs (90%), almost all via the agents' own disclosed reasons. For your harness: make intent a required argument on consequential tools, keep the journal outside the agent's workspace, and surface contradictions as first-class timeline findings. Credibility: medium-high (KTH group, open prototype, mechanical ImpossibleBench oracle, human-rated disclosure with κ=0.72). Weight: high. Complements Nov 3's RECEIPT return assumption (2611.01930) and Nov 4's Silent Instrument Errors (2611.04399): those ask what actually ran or graded; this asks what the agent claimed it was doing.

2. **[Signed, Sealed, Leaked: Trust Beyond Signature for MCP Toolchains](https://arxiv.org/abs/2611.06585)** (arXiv 2611.06585), a signed MCP tool can still leak through an allowed destination
   Signatures and destination allowlists (including Meta's MCPGuard-Dynamic) prove who published the bytes and where the process may connect — not which items each call may carry. The authors show a signed OCR tool that stashes HR data from an earlier call and appends it to the next authorized OCR request: MCPGuard blocks raw exfiltration to unlisted hosts in every trial, yet misses this carry-over in every trial under all seven configurations. Their fix is germline execution: fork each call from a data-free germline process, give each copy only the items its destination is cleared for, and discard the copies after. Across 153 attack runs, no unauthorized disclosure was detected under germline; single-copy calls took 10–49 ms. For your harness: treat MCP servers as untrusted code even when pinned and signed; bind authority to per-destination item views, not just to hosts. Credibility: medium-high (formal sink-noninterference proofs, matched MCPGuard comparison, open prototype assumptions stated). Weight: high. Complements Nov 4's MCPGuard SDK conformance gaps (2611.03662): yesterday the official SDKs didn't enforce the spec; today a correctly confined, signed tool still leaks if state survives across calls.

3. **[Can Coding Agents Sustain Continual Evolution without Forgetting?](https://arxiv.org/abs/2611.03219)** (arXiv 2611.03219), a harness that evolves for the next task type can erase the last one
   Harness self-evolution (AHE, Meta-Harness) looks strong when you evolve on one benchmark at a time — Meta-Harness hits 94% on SWE-Bench — but after further evolution on FeatureBench that same harness drops to 32% on SWE-Bench (66% relative drop). Across six cross-task directions the pattern holds: verification gates, workflow prompts, and budget strategies tuned for the new task conflict with the old one. Artifact/submission gates alone can take SWE-Bench from 96% to 0%. For your harness: if you let the system rewrite its own prompts, tools, or stop rules from trajectories, keep a retained harness per task family (or an explicit conflict check) instead of one mutable runtime. Credibility: medium (single-author empirical study, DeepSeek-V4-Flash only, sampled subsets of 30–50 tasks; the conflict taxonomy is useful even if absolute scores move). Weight: high. Pairs with the next item: search can find a better harness, but continual search without retention is a trap.

4. **[HarnessFlow: MCTS-Guided Harness Optimization for LLM Agents](https://arxiv.org/abs/2611.06254)** (arXiv 2611.06254), search the whole harness as code under a limited eval budget
   HarnessFlow treats the harness as a complete executable codebase and runs MCTS over refinement trees: a coding agent edits selected parents using a reusable component library and archived traces, while a selection policy balances score and underexplored branches. With 15 refinement attempts per benchmark it averages 69.48% across six agentic/coding/web suites, beating Vanilla by 10.89 points and Meta-Harness by 3.95, at lower average inference cost than hand-engineered baselines. For your harness: if you automate harness edits, keep the search tree (so you can revisit parents) and a validation set that covers the task families you refuse to forget — not a single leaderboard. Credibility: medium (MSRA/academic collaboration, fixed GPT-5.4-mini executor, clear ablations on library and exploration). Weight: medium-high. Complements the continual-forgetting paper: this is how to search; that paper is why the objective and retention set matter.

5. **[Trace2Eval: Contextualized Evaluation of Coding Agents from Real-World Traces](https://arxiv.org/abs/2611.06506)** (arXiv 2611.06506), rebuild the user's starting workspace from the trace, then grade the delivered artifact
   Static SWE-style benches miss open-ended delivery quality. Trace2Eval reconstructs ⟨query, initial workspace, environment⟩ from anonymized online coding-agent traces, runs a candidate agent there, and scores the artifact with human-grounded rubrics across accuracy, code quality, and UX — then feeds diagnoses back as revision instructions. Mean total score rose 10.05 pp across 19 model–harness configs after rubric-guided repair (up to +19.28 pp for DeepSeek-V4-Pro under Claude Code). For your harness: treat the recovered initial context and the UX dimensions (interface, information presentation) as part of "done," and make rubric feedback a first-class revision verb rather than another chat turn. Credibility: medium (large pipeline paper; recovery acceptance ~82.6% / replay 0.92; human–judge agreement varies by dimension; traffic is one provider's June–July 2026 sample). Weight: medium. Complements Nov 4's Vibetrace (2611.04466) and Silent Instrument Errors: traces as the eval source, not only as the UI object.

6. **[Task-efficient agent evaluation using cached traces](https://arxiv.org/abs/2611.06803)** (arXiv 2611.06803), score a new harness from one cached task by comparing how it behaved, not only whether it passed
   Full agentic benches are expensive. trubric asks an LLM for a task-specific structured summary of each trace (understanding, localization, editing, verification, …), embeds the fields, and builds a geometry of systems that predicts full-benchmark score. Combined with item-response theory, one random SWE-bench Verified task cuts mean absolute error from 0.13 to 0.08; the combo dominates baselines at every task budget when references are available. For your harness: keep graded reference traces, and when you ship a harness change, sample a few tasks and place the new run in that geometry before claiming a leaderboard move. Credibility: medium-high (clear leave-one-family/harness protocols, Wilcoxon tests, seven embedding ablations; DARPA-funded). Weight: medium. Complements Trace2Eval and Nov 4's Silent Instrument Errors: cheap relative scoring from traces, with the caveat that the grader still needs honest instruments.

7. **[MCP-Eco: A Linked Dataset of MCP Servers, Consumers, and Development Activity](https://arxiv.org/abs/2611.06897)** (arXiv 2611.06897), finally join servers to the repos that declare them
   Prior MCP corpora listed servers or host clients, but not which projects actually configure which servers. MCP-Eco freezes ~16.9M records across 19 tables: 78k candidate servers, 16k consuming repos, 9.2k parsed config declarations (5,975 resolved), plus tools/resources/prompts tagged probe vs directory, and linked PRs/issues/commits. For your harness: when you decide default allowlists or approval policies, query who actually declares a server and whether advertised capabilities match probed ones — don't trust a directory row alone. Credibility: medium (snapshot with stated false-positive risk; semantic match precision not yet measured; useful as infrastructure). Weight: medium-low / skim. Complements the Germline paper and Nov 3's When Neither Side Confirms (2611.02527).

**Takeaway for a non-chat+diff harness:** Require a typed intent on every consequential tool call and check it against observed effects. Don't treat a signature or an egress allowlist as item-level confidentiality. If the harness rewrites itself, retain per-task-family versions or you will optimize away yesterday's workflow. Use real traces both as the steering surface and as the cheap way to score harness changes.
