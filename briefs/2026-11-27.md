# Agentic & AI interface brief — 2026-11-27

**Theme: A setting is only a control if the client can find it, and a change is only an improvement if you count what it broke.** A light holiday day (arXiv didn't post a new list today), but four of the items point the same way. ACP has no standard place for "when does the agent ask me", so every client special-cases each agent's `mode`. Quota and spend limits never reach the client at all, except as Markdown. Harness self-improvement turns into a regression unless you count the successes it breaks along with the failures it fixes, and cheap-model delegation is only worth it when cost is shown next to quality per subtask. For a non-chat harness: give approval policy and budget their own typed, discoverable controls. Score every harness change as recovered vs. regressed on paired runs, and keep a human "accept / revise / reject / defer" as a recorded decision, not a vibe.

1. **[ACP RFD #3003: a `permission` config-option category](https://github.com/agentclientprotocol/agent-client-protocol/pull/3003)**: give "when does the agent ask before acting" its own discoverable slot
   Opened 11/27 (RFD only, +135 lines). Today the approval setting rides under `mode`, which also carries plan modes and personas. `claude-agent-acp` and `codex-acp` send approval presets as `mode`, Antigravity mixes approval and planning in its modes, OpenCode's `mode` picks a build or plan agent, and `codex-acp` already had to invent `collaboration_mode` for plan mode. The proposal adds a `permission` category (e.g. `currentValue: "workspace-write"`) with options ordered most to least restrictive, the same way `speed` (stabilized in #2997 yesterday) runs slowest to fastest. It follows #1063 but leaves out sandbox policy. Pairs with 11/25's When Answering Is Administering: if approval policy is a first-class, ordered control, a client can show it as a persistent dial, mark any loosening clearly, and log changes as policy edits rather than mode switches. For your harness: keep approval policy and work style (plan / build / persona) as two separate controls in the UI, ordered by restrictiveness so "loosen" is visible and can require confirmation. Credibility: medium (an RFD from a contributor, not yet reviewed or in Draft; the problem survey of existing adapters can be checked against the code). Weight: medium-high.

2. **[ACP RFD #2316: Quotas and Limits](https://github.com/agentclientprotocol/agent-client-protocol/pull/2316)**: budget state as a typed stream, not Markdown from `/status`
   Open since 10/06 and updated 11/27. It proposes a `quota_update` session update (a full snapshot), a `quota/read` request (with or without a session) and a structured `quotaExceeded` error that says which limit was hit and when it resets. A snapshot is an ordered list of pools (plan allowance, per-model allowance, credits, overage budget), each holding meters (5-hour window, weekly window, balance, spend cap). Every field is optional, so nothing is synthesized, and quota stays separate from context occupancy (`usage_update`) and token usage. Its survey of eleven agents is the useful part. Claude Code knows its 5-hour, 7-day and per-model windows plus an overage pool, but over ACP they reach clients only as a raw `_meta` blob that is dropped when no context reading exists yet. Codex knows per-bucket windows, credits and a spend cap, and forwards none of it. Gemini CLI turns quota errors into a text 429 and drops the retry delay. Copilot CLI forwards nothing. Fleet complement to yesterday's parallel-subagents cost result: you can't show cost next to gain if the limit state never reaches the client. For your harness: make budget a standing surface (pools → meters → reset time) that comes before any fan-out decision. Treat "quota exceeded" as a typed pause with a reset time and a choice (wait, switch pool, stop), not a failed turn. Credibility: medium (detailed RFD with a checkable survey; long-running and not yet accepted). Weight: medium-high.

3. **[TransHarness: From Benchmark Overfitting to Transferable Harness Evolution](https://arxiv.org/abs/2611.33757)** (arXiv 2611.33757): a harness change pays off only if what it recovers outweighs what it breaks
   HUST, China Unicom, Xiamen and BJTU authors evolve *intervention policies*: a trigger on observable execution context plus diagnostic guidance pointing the agent at task requirements and evidence. The policies come from contrasts between successful and failed runs of the same task, then pass cross-task replay and an independent semantic review so they hold up beyond their source tasks. Evolved from only 300 source trajectories outside the test distribution, they report 76.4% on DeepSWE v1.1 and 95.5% on Terminal-Bench 2.1, 2.4 and 5.6 points above GPT-6 Astra. The more useful part is the accounting. They show that Meta-Harness gains on its evolution set but loses on DeepSWE, and that an evolved simple harness still trails mature OpenCode. They then derive why: as baseline success rises, fewer failures are left to recover and more successes can regress, so the allowed regression-to-recovery ratio shrinks. They report recovered and regressed percentages from paired runs, and their difference is the net gain. Same lesson as 11/26's PRECEPT / Poisoning and 11/18's Agent Skills Go Stale: an automated rule edit needs a regression test before it ships. For your harness: when a hook, rule or skill changes, show "recovered N / regressed M" on paired replays instead of a single score delta. Show each intervention's trigger and how often it fired, so a user can see when it interrupts a run that was going well. Credibility: medium (nine authors, multi-model and multi-harness, with a careful paired-outcome method; the SOTA claims are benchmark-bound and include verifier-defect corrections the authors applied themselves). Weight: medium-high.

4. **[Partial Routing: Trace-Tuned Delegation for Resource-Efficient Agentic Workflows](https://arxiv.org/abs/2611.33402)** (arXiv 2611.33402): delegate subtasks, not tasks, using measured per-subtask quality and cost
   Arya and Jain (Toronto / Georgian). An LLM annotator finds recurring subtasks in past solo runs of a frontier lead and a cheaper worker, and an LLM judge scores each model on each one. The measured cost and quality gaps become delegation guidance in the lead's prompt, with a knob δ for how much to hand off. The lead decides when and what to delegate, and no weights change. At δ=0.75 the ViBench score rose from 70.2 to 78.5 at 19% lower cost, and the Terminal-Bench 4.0 pass rate from 54% to 61% at similar cost. A notable side result: giving the lead only the subtask breakdown, with no worker, also cut cost, and on Terminal-Bench the plan alone got 58.7% at 16% lower cost. The authors say plainly that this is one model pair per benchmark, 10 held-out ViBench apps × 3 runs and 23 Terminal-Bench tasks × 2 runs. Fits with yesterday's subagent study, where most of the gain was checking and fresh context, not more agents. For your harness: show delegation as a per-subtask table (who did it, measured quality, cost), give the user one δ-style "how much to hand off" control, and show the plan breakdown as a cheaper alternative to fan-out. Credibility: low-medium (two authors, small held-out sets, LLM-judged subtask quality; the mechanism is cheap to replicate on your own traces). Weight: medium.

5. **[The Socratic PAUSE: safeguarding scientific judgement at AI speed](https://arxiv.org/abs/2611.34222)** (arXiv 2611.34222): an AI contribution stays provisional until a person records accept, revise, reject or defer
   Celik and Al-Hashimi, a position paper. AI speeds up discovery far more than justification, and confidence outgrows evidence through recursive reinforcement, lost provenance and miscalibrated reliance, piling up "verification debt". Their fix is a checkpoint at consequential decision gates: Pin down the claim, Ask and challenge, Uncover assumptions and alternatives, Scrutinise the evidence, Exercise judgement. It ends in a *recorded* decision to accept, revise, reject or defer. They present an evaluation framework but no results. It carries over directly to code review: it's the human side of 11/26's AI-reviewer result (advice with a miss rate), and "defer" is the state most approval UIs lack. For your harness: at merge and deploy gates, mark agent claims as provisional until someone decides, make "defer (with reason)" a first-class outcome next to approve and reject, and store which evidence was looked at with the decision. Credibility: low-medium (two authors, no empirical evaluation, aimed at science rather than code; useful as a checklist for the decision record). Weight: medium-low.

**Also noted:** [ACP RFD #2995 live voice sessions](https://github.com/agentclientprotocol/agent-client-protocol/pull/2995): half-duplex base level, optional full-duplex with barge-in. `voice/interrupt` reports `playedMs` so the transcript matches what the user actually heard. Transcripts are the record, raw audio is never kept, and spoken permission answers map to explicit options, never inferred. Worth copying if you add voice. [From Conversations to Commitments (Talea)](https://arxiv.org/abs/2611.33373) (2611.33373): signed AT Protocol records plus A2A for agent-to-business deals. AT Protocol covers 5 of 6 coordination needs, and a deterministic release interface can't bound disclosure once negotiated values depend on private state. A design study only. [What Must LLM Agents Communicate?](https://arxiv.org/abs/2611.33318) (2611.33318): passing local probability estimates between agents can throw away the information a joint decision needs, so handoffs should carry evidence, not verdicts. [MGMem](https://arxiv.org/abs/2611.33174) (2611.33174): deterministic, provenance-preserving agent memory that returns the raw past turns instead of LLM summaries.
