# Agentic & AI interface brief — 2026-10-05

**Theme:** Review is the bottleneck, so make it a ledger. Agent diffs should be reviewed as stateful, risk-ranked objects (content-hashed "viewed" state, intent and drift signals, a spotlight on where to look) rather than one flat patch, and the protocol and host layers are starting to carry the structure that needs: first-class child sessions, host-drawn side panes, and one contract artifact for both live gating and after-the-fact audit.

1. **[diffthing](https://github.com/rahXephonz/diffthing)**: review state that survives a still-editing agent
   Groups hunks into named scopes and an ordered walkthrough. It tracks viewed, changed-since-viewed, commented, and resolved state by content hash, so live agent edits can't quietly keep a stale approval. Impact is scored deterministically ("LLMs never decide risk or correctness"), anchored questions and change requests go back to the running agent, and the Git index is the approval ledger: a file is staged only once every hunk is viewed and no comment is open. That's the most concrete "review as ledger" design I've seen, and it's directly stealable for a non-chat harness. Credibility: medium. It's an early v0.1 OSS project (about 19 stars, actively pushed) with no evaluation, so the value is in the design. Weight: high.

2. **[Trust-Calibrated Code Review (arXiv 2606.01969)](https://arxiv.org/abs/2606.01969)**: JetBrains participatory design for multi-file agent changes
   Its conclusion is the headline: reviewing LLM-generated multi-file changes is a trust-calibration problem, not a diffing problem. It proposes a three-level workflow (overview, file analysis, snippet review) built from seven constructs: chunk, risk-per-line, risk-per-file, judge, walk-through, zoom in/out, and security cage. It's a good vocabulary for the review surface and pairs naturally with diffthing's scopes and scores. Credibility: medium-high. The study had 17 practitioners in discovery and a prototype survey of 43 (all three levels scored above neutral, and 63% expected less review effort), but there's no controlled task study. Weight: high.

3. **[ARCTIC: Intent, Drift, and Spotlight (arXiv 2607.29516)](https://arxiv.org/abs/2607.29516)**: what to show the reviewer
   This paper reframes review around three signals. It infers intent from conversation logs, measures drift between that intent and the agent's output by backtranslation, and spotlights the diff regions most worth human scrutiny. The authors report intent prediction at 0.86 F1, drift agreement with humans at QWK 0.907, and a spotlight 2.4x better than a baseline AI reviewer at 5x fewer tokens. In a rollout, drift scores cut misalignment by 5.76 points (p = 0.026). For a harness the takeaway is that the session transcript is review input: show intent-vs-output drift beside the diff. Credibility: medium-high. The scale numbers are self-reported by the system's authors from a taxonomy of 18,000 reviews. Weight: medium-high.

4. **[ACP subagents RFD (merged Sep 30)](https://github.com/agentclientprotocol/agent-client-protocol/pull/1992)**: child sessions become a protocol object
   It shipped as unstable in Schema v1.24.1 and Rust v1.10.x. A single upsert-style `subagent_update` carries a child session ID, task, and work state. Work state (`running`, `idle`, `unknown`) is kept separate from connection loss, so clients must show a local "disconnected" status instead of guessing success or failure. A child's pending permission requests and elicitations (the protocol's mid-task questions to the user) have to resolve or cancel before its terminal update. The spec also covers replay on reconnect. If your fleet or tree UI needs agents' own sub-dispatch rendered as child transcripts rather than flattened tool calls, this is the wire shape to build to. Credibility: high, since it comes from the primary protocol repo with review from JetBrains AIR and adapter implementers. It's still unstable, and the maintainers say the adapters still need updating. Weight: high.

5. **[Claude Code 2.1.287–2.1.289: Claude Mods and "You should know"](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)**: host-drawn panes plus a side-agent watcher
   Mods let plugins change deeper behavior and draw their own bands, panes, and regions in the TUI, with an agent-launch hook (`agent.spawn`) that can now block or rewrite teammates too. The new APIs include `$.ui.selection()`, and when a mod's view crashes it raises a `ui.fault` and fails on its own while the session keeps running. The built-in "You should know" mod runs a side agent that watches longer tasks and posts notes above the prompt, attributed to "we", "the main agent", or "you". That's an ambient-supervisor pattern, not another approval card. It's worth copying both the extension point (third-party surfaces with fault isolation) and the attribution detail. Credibility: high for what shipped, since it's Anthropic's official changelog, but public docs for the Mods API are thin and "You should know" needs first-party sessions with telemetry on. Weight: medium-high.

6. **[ContrAgent: Symbolic Temporal Supervision (arXiv 2609.18128)](https://arxiv.org/abs/2609.18128)**: one contract for live gating and offline audit
   Assume-guarantee contracts written in finite-trace temporal logic (LTLf) are compiled to deterministic state machines. The same artifact gates tool calls online and grades recorded traces offline, and the contract library is independent of the model, so it's reusable across agents. On four benchmarks it matches LLM-judge and rule-based guardrails with deterministic verdicts and orders-of-magnitude lower per-call latency. It complements go-steer's plan-artifact gate and OCL from Friday: the gate and the audit view can share one source of truth, which makes "why was this blocked?" answerable and diffable. Credibility: medium-high. It's a fresh arXiv paper (Sep 16) without a shipping UI, and the formal-methods authoring burden is real. Weight: medium.

**Takeaway for a non-chat+diff harness:** Treat review as durable state. Content-hash "viewed", let the index or ledger hold approvals, and rank attention by risk, drift, and spotlight instead of handing over a flat patch. Model child agents as real sessions with honest unknown and disconnected states, leave room for side-agent watchers and third-party panes, and let one compiled contract drive both the live gate and the audit trail.
