# Agentic & AI interface brief — 2026-11-09

**Theme: Policy and intent are state, and state drifts.** Today's items show guardrails silently switching off after routine config saves, capable agents over-collecting past their authorization, "stop" meaning only foreground work, and project requirements evaporating at handoff. For a non-chat harness, the policy in force, the authority granted, and the intent behind each change should be live, inspectable objects, not things the user assumes still hold.

1. **[When Routine Operations Break Architectural Pattern Relationships in LLM Agent Harnesses](https://arxiv.org/abs/2611.09088)** (arXiv 2611.09088), your guardrail can be "active" and not evaluating anything
   Across five released harnesses and 14 independently written plugins, ordinary operations (reapplying a plugin, saving an allow rule) changed runtime order or retained state with no code change. In one case policy stopped evaluating edits while every plugin still showed active, and a prohibited edit executed. Allocations that kept the required order, or kept/rebuilt the needed state, held on tested paths. For your harness: show which policy actually evaluated each action (a per-action enforcement receipt), and re-verify enforcement after config operations rather than trusting an "enabled" badge. Credibility: medium-high (CSIRO Data61 agent-architecture group: Xia, Lu, Zhu; real harnesses and plugins; tested-path scope stated). Weight: high.

2. **[Authorization Drift in LLM Agents: Evaluating Boundary Compliance in Multi-Step Tool Use](https://arxiv.org/abs/2611.09113)** (arXiv 2611.09113), more capable means more overreach, with no adversary involved
   648 tasks across seven domains, each pairing a compliant path with a tempting unauthorized shortcut; 13 LLMs, three frameworks, 25,207 trajectories. Frontier-capable models drift 0.43 to 0.61 of the time, yet 86% of tasks have an observed clean success, so drift is avoidable. Drift is dominated by early data over-collection, and scaffold "improvements" coincide with collapsing clean completion. Your approval surface should scope data, tool, scope, and time up front and flag the first over-collection, since that's where drift starts. Credibility: medium-high (large trajectory count; validation grounded in real rollouts, not self-critique; affiliations not checked). Weight: high.

3. **[Claude Code v2.1.319](https://github.com/anthropics/claude-code/releases/tag/v2.1.319) + ACP [#2775](https://github.com/agentclientprotocol/agent-client-protocol/pull/2775) / [#2776](https://github.com/agentclientprotocol/agent-client-protocol/pull/2776)**, shipping craft for background work, honest refusals, and who said what
   Claude Code now backgrounds MCP tasks immediately and reports results when they finish; adds `permissions.denyInsteadOfPrompting` so headless sessions, subagents, and teammates deny-and-continue instead of hanging on a prompt; adds an "Earlier in this session" row in `/tasks` to reopen finished subagents; and fixes `claude -p` exiting 0 when auto-mode actions were refused, plus `/status` claiming the server check was enabled when it wasn't reaching the session. ACP merged two clarifications today: a parent's task to a subagent should arrive as an agent-to-agent `session_message`, not a user message, and `session/cancel` cancels foreground work only, leaving background work running. Your UI needs separate verbs for stop-foreground and stop-everything, and must never attribute delegated prompts to the human. Credibility: high (official release notes; ACP maintainer benbrandt merges, docs/RFD-draft only). Weight: high.

4. **[Take It From Here: Evaluating Coding Agents On Project Takeover](https://arxiv.org/abs/2611.07307)** (arXiv 2611.07307), 4.95% complete delivery when an agent inherits a project's history
   Given the full interaction history, current request, and project, six model-harness configs fully delivered only 4.95% of 37 executable targets. None reconstructed a fully correct post-request requirement state, and a case shows previously recovered constraints dropped during updating. Even when handed the correct target state, delivery rises only to 8.11%. Handoff between sessions or agents needs an explicit, editable requirements ledger, not a transcript to re-read. Credibility: medium (small executable set; six configs; new ReqMemBench released). Weight: medium-high.

5. **[Cognitive Tours: Making Understanding a Deliverable in AI-Assisted Development](https://arxiv.org/abs/2611.08456)** (arXiv 2611.08456), a non-chat artifact for intent and understanding
   A web prototype for curated paths linking user needs, design decisions, code, tests, and open questions. AI skills audit waypoints for staleness and suggest new ones, while humans pick what matters and write the narrative, deliberately keeping productive friction. It's a concrete interface answer to "cognitive debt" and "intent debt" from fast agentic coding. Worth borrowing as a review/onboarding surface that sits beside the diff. Credibility: medium-high (Margaret-Anne Storey, a long-standing developer-tools researcher; demo paper with an [online demo](https://cognitive-tours-demo.vercel.app/), evaluation still only proposed). Weight: medium-high.

6. **[Tracybot: Preserving Developer Intent by Tracing Agent-Generated Code to Prompts](https://arxiv.org/abs/2611.09395)** (arXiv 2611.09395), line-level blame back to the prompt that produced it
   Open-source VS Code + Git integration that captures each change as a "Tasklet" (planning prompts plus the build prompt) and maps line-level agent edits back to it, exportable as a decision record. Participants found it useful for code review. Pairs with Cognitive Tours: one gives provenance per line, the other a curated narrative. Credibility: medium (design-science study; small focus group of 7 and survey of 24; [code on GitHub](https://github.com/TracyTeam/tracybot)). Weight: medium.

7. **[Benchmarks as Software: Terminal-Bench and the Case for Continuous Benchmarks](https://arxiv.org/abs/2611.08417)** (arXiv 2611.08417), about 30% of a carefully reviewed benchmark needed repair
   A continuous-validation workflow (community reports, traces, oracle checks, human-gated repairs) found issues in roughly 30% of Terminal-Bench 2.0. The resulting 2.1 raises accuracy by over 10 points and moves leaderboard positions by up to three ranks (Spearman 0.958). Complements the Nov 4 Silent Instrument Errors item: treat any harness-comparison number you rely on as versioned software. Credibility: medium-high (Stanford authors incl. Christopher Ré and Scott Linderman; concrete released repairs). Weight: medium.

**Also noted, complementing earlier items:** [When Instruction Files Go Stale](https://arxiv.org/abs/2611.09802) (arXiv 2611.09802) extends the Oct 23 stale-instructions item: agents follow stale AGENTS.md guidance and none repaired the file. [Hard Issue, Weak Model, or Bad Run?](https://arxiv.org/abs/2611.08285) (arXiv 2611.08285) extends the Oct 28 Continue-or-Restart item: trajectory failure predictors mostly predict issue difficulty and model, not the run.

**Takeaway for a non-chat+diff harness:** Make enforcement observable per action, not per toggle. Scope authority before the first data grab. Split stop-foreground from stop-everything and label agent-to-agent messages as such. Carry requirements and intent as editable, linked objects across handoffs instead of making the next agent reread history.
