# Agentic & AI interface brief — 2026-10-14

**Theme:** Bind every gate to a host-side object. Authority to a per-agent capability store. "Reviewed" to a durable receipt (complete input, exit status, separate pool). Allow rules to an exact server name. Session behavior to a protocol field. Fleet policy to the action about to commit. Anything left as ambient privilege, prefix match, or exit-zero-with-pretty-text is a claim, not a gate.

1. **[Cross-Provider Review as a Runtime Contract for Coding Agents (arXiv 2610.10961)](https://arxiv.org/abs/2610.10961)**: a second opinion is only a review if the harness can prove it
   The paper turns cross-provider review into a measurable contract: distinct resource pools, bounded execution, restricted reviewer capabilities, complete input delivery, usable semantic output, typed failures, and durable per-attempt evidence. In a 20-turn pilot, 8/20 had a material finding. Fault injection found three false-success paths (partial input counted as complete; cancellation during reaping still completed; nonzero exit with a well-formed verdict counted as complete). Exit status was not recorded per attempt, so the first preregistered cohort could not be scoped after the fact and had to restart. For a harness: never render "reviewed" from a green process alone — show the receipt (input completeness, exit, model provenance) or show failure. Credibility: medium-high. Controlled pilot + deterministic fault injection with honest limits (agent-authored tasks, model adjudication, proprietary OTA runtime); status as of 2026-10-07. Weight: high.

2. **[Authority Is Not a String: CapScope (arXiv 2609.08371)](https://arxiv.org/abs/2609.08371)**: ambient authority is the confused deputy
   CapScope freezes a task-wide capability ceiling from trusted input (user request + file *tree*, not contents) before any repository text is read, then gives each sub-agent its own host-side capability store checked at every tool dispatch. A runner that reads poisoned pytest output can run tests but cannot write source — the write lives only on the patcher. Across 300 runs (5 tasks × 5 injection surfaces × 4 auth conditions × 3 trials), ambient/static/global policies executed the injected effect in 33–47/75 runs; CapScope in 3/75, with 68/75 repairs completed. Complements Oct 12's Approval Laundering: field binding at the tool call is not enough when every principal shares ambient write. Credibility: medium-high. ACM LMPL '26 workshop paper, controlled factorial on Pi with released artifact; small Python repairs, one model. Weight: high.

3. **[Claude Code v2.1.299: exact MCP allows, refuse-on-hook-failure, idle compaction](https://code.claude.com/docs/en/changelog)**: prefix allow and fail-open hooks are gone
   Shipped 2026-10-14. MCP allow rules now match only the named server (`mcp__a` no longer covers `a__b` / `a_`). Plugin hooks that cannot receive an action or return an answer refuse the action; if the tool already ran, the result is withheld. Connector/MCP proxy requests no longer follow HTTP redirects. Idle 200K+ token terminal sessions compact after ~54 minutes so the next turn does not pay uncached full context. Also: plan mode no longer honors a PreToolUse/`tool.check` allow that would skip the write gate; Windows PreToolUse/PermissionRequest hooks that set no shell fail closed when Git Bash is missing. Same binding story as CapScope and yesterday's delete-approval craft — exact name, fail closed, no silent open door. Credibility: high. Primary Anthropic changelog. Weight: high.

4. **[How Do Agent Harnesses Create Value? Planning Information and Release Control (arXiv 2609.20474)](https://arxiv.org/abs/2609.20474)**: plan the task; gate the release — measure them apart
   Fixed task-specific plans beat word-count-matched Sham text by +7.17 pp oracle success (90% interval 1.15–13.36; 265 matched cells), with gains on higher-complexity tasks. A read-only terminal verifier rejects 61% of Retail oracle-invalid episodes while withholding 17% of correct ones, at <1¢/episode. Under high false-pass liability, Verifier-only captures nearly the full stack's avoided false-pass benefit at ~1/12 the incremental cost. Interface lesson: show planning gain and release control as separate metrics and separate UI affordances — a plan checkmark is not a release receipt. Credibility: medium-high. Large τ²-bench study with matched Fixed–Sham design; preprints, public-bench contamination risk, plan provenance incompletely documented. Weight: medium-high.

5. **[ACP Client-Provided System Prompt RFD → Draft](https://agentclientprotocol.com/rfds/client-system-prompt)**: stop stuffing persona into the user turn
   Moved to Draft 2026-10-12 (unstable schema landed). Clients may send a session-scoped `systemPrompt` `{mode, content}` on `session/new` (and re-send on load/resume/fork), capability-gated, with `append` as baseline and `override` behind a sub-capability. Replaces fragmented workarounds (`_meta.systemPrompt`, Goose extension methods, `[System]\n…` prepended to user messages). For a non-chat client: behavioral instructions, personas, and platform context become first-class session config — same class as `cwd` and `mcpServers` — instead of competing with user content. Credibility: high. Primary ACP RFD with surveyed harness behavior; still Draft/unstable. Weight: medium.

6. **[OpenAgentFlow: system-wide safety at the action-commit boundary (arXiv 2609.00015)](https://arxiv.org/abs/2609.00015)**: fleets need one PEP, not one policy per executor
   Control-plane / action-plane split: GUI, API, tool, and LLM-planned actions normalize into a shared `AgentEvent` stream mediated by one pre-execution Policy Enforcement Point, with provenance and session state held *outside* individual agents. New FlowRules take effect without modifying agents, prompts, or executors. 94% accuracy / 95.35% attack-block on a 300-case suite; 97.62% accuracy and 1.96% safe false-intervention on AgentDojo-Traj (1,220 cases). For a coding fleet UI: the supervision object is the pending commit plus session provenance, not the chat turn that proposed it. Credibility: medium. Systems paper with strong external-benchmark numbers; instrumentation-boundary scoped (bypass paths are out of scope). Weight: medium.

**Takeaway for a non-chat+diff harness:** Treat every gate as a binding to a host-side object you can audit: capability store per principal, review receipt per attempt, exact allow identity, protocol-level system prompt, shared action-commit PEP for the fleet. Measure planning and release control separately. Fail closed when the guard cannot answer. Never paint "approved," "reviewed," or "allowed" from ambient privilege, prefix match, or a well-formed string alone.
