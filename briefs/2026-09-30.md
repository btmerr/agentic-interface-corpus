# Agentic & AI interface brief — 2026-09-30

**Theme:** Host-owned contracts, not hope. Modes the agent cannot flip; plans as calm review artifacts; rules that demand proof before the next step; harness edits as falsifiable predictions; engines behind typed streams so UIs compose without forking the core.

1. **[Plan Mode (Grida WG)](https://grida.co/docs/wg/ai/agent/mode-plan)** — normative plan↔build contract  
   Mode is host-injected context, not model state. Agent may propose a transition; it MUST NOT effect one. Transitions are human-gated re-scoping messages. `plan` is capability-denied (one carve-out: writing the plan artifact). Spec leaves the approval UI open and forbids prompt-only “read-only.” Pair with yesterday’s plan-as-trajectory work: the gate is a regime change, not denser approve buttons.

2. **[planpage](https://github.com/YosefHayim/planpage)** — local HTML plan/review surface (`npx planpage`)  
   Plans and review-gates as terminal walls of text are hard to judge. Renders self-contained offline HTML (eight templates, Shiki-baked colour); opt-in post-back collects edit/annotate → **Send to Agent** as one JSON batch. `init` wires nine agents. Complements Builder visual plans: shipping craft for plan-as-page without owning a protocol.

3. **[Zoro: Active Rules for Reliable Vibe Coding](https://arxiv.org/abs/2604.15625)** — Ma, Wang, Kung, Chilton (Columbia); [repo](https://github.com/jennygzma/zoro)  
   AGENTS.md stays passive (context rot, invisible compliance). Enrich–Enforce–Evolve: attach rules to plan steps, block advance until `prove-rule` evidence (code + optional tests), in-situ notes → evolve ruleset. 36 sessions: rules-followed 0.51→0.80 (+57%) without hurting feature completeness; process rules 35%→87%. N=12: shift from prompt engineering to rule engineering. Rules as active UI objects, not markdown hope.

4. **[Agentic Harness Engineering (AHE)](https://arxiv.org/abs/2604.25850)** — Lin et al. (Fudan / Qiji Zhifeng); [code](https://github.com/china-qijizhifeng/agentic-harness-engineering)  
   Automating harness edits fails on opaque trajectories and unattributable changes. Three observability pillars: file-level components, layered trajectory evidence, change manifests with predicted fixes/regressions verified next round. Terminal-Bench 2: 69.7%→77.0% pass@1 over Codex (71.9%); frozen harness transfers (+5.1–10.1 pp cross-family). Ablation: tools/middleware/memory carry the gain; prompt-only regresses. Regression foresight still weak—falsifiable contracts for harness evolution, not another prompt tuner. Complements Rel(AI)Build’s deterministic control plane.

5. **[Everything Is a Stream (Ante v0.2)](https://antigma.ai/blog/2026/09/21/everything-is-a-stream)** — Antigma Labs  
   Plugin the surface; protect the plugged (eval-expensive agent core). `ante serve` exposes ops in / events out (approvals, interrupts, diffs, tokens) over stdio/UDS/WebSocket. Proofs: ~220-LOC `mini-tui`, `ante-acp` bridge into native IDE permission dialogs, Slack/Discord gateway with per-thread sessions. Interface layer as stream client—same thesis as ACP clients, argued as architecture.

6. **[control-surface-agent](https://github.com/cloudpresser/control-surface-agent)** — thesis companion to cloudpresser’s control-systems writing  
   Operator console (intent · plan · telemetry · evidence · reconciliation · controls), not chat. Reconciliation checks intent/evidence/output divergence before the decision artifact; interventions are structured signals. Incremental adoption path around existing loops. Complements 09-25 control-surfaces essay with a runnable single-run prototype aimed at longitudinal reliability.

7. **[Fleet Commander](https://github.com/culpeo-labs/fleet-commander)** — ACP fleet TUI (early, MIT)  
   Keyboard-driven client over any ACP agent in per-repo dev containers; sticky-scroll streaming; `y`/`n` permission prompts; `fleet-commander-core` session API for alternate frontends. Early APIs, but the split (core vs TUI) and container isolation match a non–chat+diff fleet director better than another single-session chat shell.

**Takeaway for a non–chat+diff harness:** Own regimes and capability at the host. Make plans and rules first-class review objects with proof gates. Treat harness changes as falsifiable contracts with rollback. Put the expensive engine behind a typed ops/events stream so supervision UIs stay swappable clients.
